THINGS A DESIGNER SHOULD KNOW THAT ARE NOT SINGLE STATES.

1. Two of the five headline sentences can never render. deltaHeadline handles declared === 0 with two carefully worded sentences (overview.tsx:285 and headline.ts:70-82), but Delta() returns a RefusalPanel on that condition before it ever calls deltaHeadline. Those sentences live only in apps/web/test/headline.test.ts. Only three of the five are designable surface, and one of the three (everything ran) has never been produced by any bundle. Design for three sentences with four renderings each: singular versus plural clause, spelled versus mono numeral.

2. The delta bar and the figure above it can disagree. buildDeltaBar protects the outside count from rounding to zero (delta-bar.ts:47-52) but does not protect the filled count (delta-bar.ts:66-67). pydantic-ai-exercised renders 120 hollow cells, a dashed boundary and one filled cell past it, under a 56px '0.3%'. The picture reads as 'nothing declared ran and one undeclared thing did', which is close to true but not what the figure says. This is the single most striking state on the screen and it is reachable today.

3. The skipped files number is wrong in two places. Both the RuledStat at overview.tsx:542 and the disclosure count at overview.tsx:580 use coverage.skipped.length, which the schema documents as a bounded sample (packages/schema/src/graph.ts:88-95), while coverage.filesSkipped is the measurement. pydantic-ai and pydantic-ai-exercised report 34 where 81 files were skipped. AGENTS.md says a report that does not state what it failed to inspect is not evidence; this understates it by more than half. Design and code need filesSkipped, with skipped.length only as the sample size behind the examples.

4. Two generated sentences are ungrammatical at a count of one, and one of them is reachable in a real fixture. overview.tsx:96 reads '1 of these joins rest on a kind and a name alone'; overview.tsx:102 reads '1 observed names matched more than one declaration', which is exactly what pydantic-ai-exercised renders today. Both need the singular-and-plural treatment that headline.ts:50-61 already implements.

5. The Joins component has a state where it renders nothing at all. When joins exist but all of them were made by strong rules (vercel-ai-chatbot-exercised), it returns a fragment of two nulls. That is the good case and it is invisible: the reader cannot tell 'every join was strong' apart from 'this report does not compute joins'. A quiet affirmative line would be the same move the delta headline already makes for the everything-ran case.

6. Three refusal panels and one whole branch are dead or near-dead. NextSteps can never be empty (every path through nextActions pushes at least one action), so the guard at overview.tsx:494 never fires. Figure's 'no rate' and DeltaDetail's 'not computable without runs' for the component rate cannot occur, because packages/graph/src/delta.ts:395 omits the rate only when runIds is empty or declaredComponents is 0, and both cases are intercepted by earlier returns in Delta(). The relation rate version of that string is reachable but says the wrong thing: with runs present and zero declared relations it still reads 'not computable without runs'.

7. One next step has never been rendered. 'Vary one dimension and compare' needs a scenario, a run, components, no failed adapter and no goal-eligible risk at once. demo-populated is the only bundle with a scenario and a run, and it has seven eligible findings, so it takes the goal branch instead. Similarly 'Correct the input that could not be read', the whole Incomplete input block, the manifest-read-but-empty step, and the four-candidate truncation all require a failed adapter, which no bundle in the corpus has ever produced.

8. Two features of the schema reach the bundle and never reach the page. UnsupportedArea.kind separates a language nobody wrote a parser for from an adapter that is behind from a defect in an adapter (packages/schema/src/graph.ts:57-63), and the overview renders all three identically. AdapterRun.detail is only visible as a title attribute on the status cell (overview.tsx:623), so on a touch device it is unreachable; four fixtures carry one.

9. Nil treatment is inconsistent inside the Coverage stat row. Files skipped dims at zero; Components and Files parsed do not, so orchescope-discovery renders a full-weight '0' over 'Components, across 0 relations' beside a dimmed '0' for skipped files. The four delta stats are all nil-aware, so the two rows behave differently.

10. Unbounded lists on the screen: the two join notes name every id with no ceiling (overview.tsx:96 and 102), 'Runs considered' joins every run id on one line (demo-populated already puts ten there), the Contradictions and Repeated side effects tables have no row ceiling, and the Adapters table has none either. Everything else on the page has a stated ceiling. AGENTS.md prohibits unbounded output.

11. The severity legend counts all findings, not the risks the block above it ranked, so on demo-populated the marks total 19 while the strengths (2) are counted nowhere in that group and the footer link above says 21. Three different denominators are on screen within one scroll.

12. The evidence key has two visually identical marks with different meanings when neverDeclared > 0: row one is a filled cell meaning 'exercised', row three is the same filled cell meaning 'ran, never declared'. The dashed boundary in the bar carries the distinction and the legend does not repeat it.

13. Density and the 390px floor. A dense bar of 120 cells at the 2px minimum plus 1px gaps needs about 359px of track. The e2e suite asserts no section scrolls sideways at 390px (tests/ui/workspace.spec.ts), so the bar is close to the edge at the ceiling; anything that adds horizontal padding to the main column at that width will push it over.

14. Fixture coverage summary for this screen. Never reached by any bundle: a critical finding, an info finding, an unranked severity, an unknown basis, a failed adapter, a contradiction, a truncated scan, a bar between 49 and 120 cells, a scan over a minute, bytes under a kibibyte, a report with strengths but no risks, and the benchmark next step. demo-populated is the only bundle reaching the spelled headline, a dirty working tree, a duplicate side effect, a simulated basis, plural runs, and the mostly-available capability table; pydantic-ai-exercised is the only one reaching the bucketed bar, the zero-filled bar, the ambiguous-join note and the skipped-examples truncation; orchescope-discovery is the only one reaching the no-risks refusal, the missing severity legend and the manifest next step. Those three plus vercel-ai-chatbot-exercised cover most of what is reachable; everything in the list above with reachedBy 'none' needs a hand-edited bundle.
