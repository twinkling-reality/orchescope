## What this is

Orchescope reports the difference between what an agent system's repository DECLARES and what its runs
EXERCISED. That join is the product. It ships as a CLI and an MCP tool.

## The invariant this work exists to hold

    1. Protocol, framework-blind. MCP, OpenTelemetry GenAI semantic conventions, OpenAI-compatible
       HTTP path shapes.
    2. Structural, framework-blind. Imported-construction shapes, effects.
    3. Bounded refusal. Anything layers 1 and 2 see and cannot NAME is said out loud, with a source
       location.
    4. Framework adapters. Depth only. NEVER required for correctness.

**DO NOT FIX ANYTHING BY ADDING A FRAMEWORK ADAPTER.** Every defect below lives in framework-blind code.
If you find yourself writing an adapter named after a framework, you have taken the wrong branch.

**DO NOT FIX ANYTHING BY ADDING NAMES TO A LIST.** Adding strings to a vocabulary array is the disease,
not the cure. If a fix reduces to "and also match `foo`", it is wrong. The one exception already litigated:
a table that says who OWNS a name (a language's own standard library, a bundler's declared path aliases) is
provenance and is allowed, because it can be asked of the runtime rather than maintained by hand.

## What already landed (18 commits on `d2c3720`). Do not redo any of it

- **Provenance gates** before any widening: a language's own standard library (Node's `builtinModules`,
  Python's `sys.stdlib_module_names`), bundler root aliases reusing `symbol-index.ts`'s existing
  `ROOT_ALIASES`, and first-party Python packages including PEP 420 namespace packages.
- **Defect A**: the tools-AND-model conjunction is gone. A key is split into words and matched against
  stems, so `modelPath`, `model_client`, `chatModel` and `systemPrompt` are one stem written four ways with
  none of them written down. Two suppressors keep it precise: an OpenAI tool-schema payload, and a
  declaration builder (every field a call, at least one rooted at the callee).
- **N4, the bound-receiver bridge**: `this.c = new C()` then `this.c.chat({model})`.
- **Defect B**: inference recognised by a version-anchored OpenAI-compatible path shape independent of
  host; recognised host yields a named provider, unrecognised yields `model:unspecified/<name>` with no
  provider component and no `served_by_provider` edge; both halves refuse when neither is settled. Also a
  pre-existing bug fixed: `hostToAskAbout` now strips port and credentials.
- **Defect C**: the function enclosing a bare model call is an **inferred entry point**, not an agent, and
  reuses the vocabulary `effects.ts` already mints. `establishesAgentSystem` learned to ask about the frame
  directly so a repository whose model and provider are both selected at run time still reports as an agent
  system.
- **The terminal overflow row** names the states it dropped rather than only counting them.
- **All eight acceptance targets pinned** as corpus entries, five with exact bounded acceptance contracts.

## Two things that were built, measured and REFUSED. Do not rebuild them blind

Both were attempts at a "tier B" floor that would make silence impossible rather than unlikely.

**Broad form**, every foreign construction with no argument predicate: names `react` 362 times on one
application, 48 distributions on another, 21 on `open-agent-platform` (the pinned entry ADR 0004 turns on),
and puts a refusal on the acceptance negative control that passed cleanly.

**Narrow form**, base classes and decorators only: a 14-repository sample supported it; the **full corpus
moved 24 of 48 entries** with `pydantic.X(BaseModel)`, `click` command decorators, `pyqt6.X(QWidget)`,
`discord`, `streamlit`, `@angular/core.@Component`, and on three entries the data models evicted the real
construction out of the bounded sample.

The reason, and it is the crux of the remaining work: **a base class and a decorator are how every Python
library asks for a declaration, not how agent frameworks do.** Nothing structural separates
`class AgentWorkflow(Workflow)` from `class Invoice(BaseModel)`. Separating them needs a vocabulary of
framework names, which is the thing being removed.

If you find a signal that does separate them, measured over the whole corpus and not a sample, that
reopens the floor and with it the literal form of the invariant. That is the single highest-value thing in
this document.

## The remaining work

Ordered by how much of the invariant each one holds up. Each is verified; each cites source.

### 1. Layer 1 is only half framework-blind. This is the next thing that falsifies the invariant

MCP recognition has two bases. Configuration files keyed on `mcpServers`/`servers` are genuinely
protocol-shaped and package-blind. But the SDK call sites are gated on a three-entry distribution
allowlist at `packages/discovery/src/adapters/mcp.ts:38`:

    const SDK_PACKAGES = ['@modelcontextprotocol/sdk', 'mcp', 'fastmcp'];

used as `adapter.packages` at `:238` and as the applicability gate at `:479` and `:481`. That is
structurally the same object as the twelve-entry host allowlist defect B removed. The invariant names MCP
as layer 1, framework-blind, and half of the MCP reader is not.

MCP is a **protocol**: a JSON-RPC method vocabulary (`tools/list`, `tools/call`, `initialize`), a stdio or
HTTP transport, and a server manifest shape. `packages/instrumentation/src/outbound-fetch.ts` already
recognises a protocol call from a JSON-RPC document without knowing the library. The static half should be
able to do the same. A fourth SDK is not a fourth entry in that array.

### 2. A construction with no arguments is silent

`packages/discovery/src/unclaimed-imported-construction.ts:149` `objectEntries` returns `[]` for any
argument that is not an object or a keyword bundle, so

    agent = create_agent(config)      # one identifier argument
    agent = build_agent()             # no arguments at all

from a distribution no adapter claims produce nothing. Every shipped predicate reads argument names and
these have none to read. This is why the invariant is held in a weaker form than its literal statement:
silence is narrowed, not eliminated. See the refused floors above before proposing a cure.

### 3. Subclassing and decoration are invisible in both languages

`a3a27ec` taught the JavaScript analyzer to record a base class in `DefinitionFact.initializer`, matching
what Python already did, **and nothing consumes it**. `class AgentWorkflow(Workflow)` with five `@step`
methods, the LlamaIndex shape the acceptance check recorded as silent, is still silent. The corpus entry
`workflows-acp` is pinned as a known limit and holds exactly that.

### 4. Non-call declaration sites were never built

- **Annotations.** `packages/source-analysis/src/facts.ts:231-232,247` carry `returnAnnotation`, `returns`
  and `ParameterFact.annotation`. `def handle(agent: Agent) -> AgentResult` names an unclaimed
  distribution with no call and no construction anywhere.
- **Re-exports.** A third-party symbol re-exported through the repository's own module is refused as local
  before any test runs: `from .llm import Agent`. Wrapping a library in an internal module is among the
  most common production shapes there is. `SymbolIndex` already resolves across modules.

### 5. Layer 0 can be silent before any layer runs

`packages/discovery/src/discover.ts:116` `LANGUAGE_MARKERS` is an eight-entry extension list, and its own
comment is honest about it: "what a real repository turns out to contain rather than what a survey says
exists." A repository in Elixir, Scala, Dart or Lua produces no `language_not_analysed` area at all, and
the closed-world sentence is emitted with nothing beside it. The backstop cannot help, because the file was
never a candidate. Detecting "a file this build did not read, in a language it does not name" is the fix.

### 6. `langchain_core` is read by two adapters and claimed by none

`matching.ts` `moduleMatches` needs an exact match or a `name/` or `name.` prefix, so the Python spelling
`langchain_core` misses the claimed `langchain`. It is read at
`packages/discovery/src/adapters/langchain-legacy-agent.ts:349` and
`packages/discovery/src/adapters/langchain-prompt-template.ts:20` but appears in no adapter's `packages`,
so its constructions land in the refusal list rather than on `adapter_found_nothing`. Adding it to an
adapter's `packages` changes applicability through `projectUses` and could mint components, so it needs its
own measurement. **This is a claim-list correction, not a widening.**

### 7. Known limits to state, not necessarily to fix

- **`tiny-code` (T7)** declares five tools as plain Python dicts with a `TOOLS` dispatch table and no
  import from anything. An imported-construction reader cannot see a declaration that imports nothing.
- **Ollama's native `/api/chat` and `/api/generate`** are not inference paths. Verified:
  `isInferencePath('/api/chat')` is false, and `/api/show` is correctly false too, so the operation list
  does discriminate. Teaching it two more operations is a layer 1 protocol-vocabulary decision with its own
  false-positive surface, not a framework fix.
- **A streamed or protobuf request with no readable `model` field** produces a runtime span the static side
  cannot name, and the reverse.
- **A repository declaring one model id under two providers** loses the bare-name join, because
  `unspecified/<model>` removes the exact match that would have won.

### 8. Hygiene found in passing, all verified, none fixed

- `tests/e2e/rule-input-producers.test.ts` does not assert what its own doc comment claims. It filters
  `COMPONENT_KINDS` down to kinds a rule file literally names, so a new kind no rule mentions is asked
  nothing and the test passes green. Do not treat it as the gate for a schema change.
- `schemas/manifest.v1.json` and `manifest.v2.json` are not emitted by `scripts/emit-schemas.mjs` and not
  compared by `--check`. They already omit `workflow` and `workflow_step` from their `ComponentKind` enum
  while the live readers accept both.
- **No compile-time safety on component kinds anywhere**: no `Record<ComponentKind, …>`, no switch, no
  exhaustiveness helper. Every kind population is a `Set<string>`. Two are already stale:
  `packages/findings/src/rules/static-policy.ts:1089` keeps deleted `worker`, and
  `packages/report/src/exports.ts:30` keeps deleted `project` and omits live `evaluator`.

## Hard rules

- **NO GUESSING.** Verify every claim against source before acting on it. Cite `file:line`.
- **Gates that must be green before you say anything is done.** Report real numbers, never "tests pass":

      pnpm check              exit 0
      pnpm test               1696 pass, 0 fail, 364 suites
      pnpm test:metamorphic   576 pass, 0 fail
      pnpm corpus             48 matched, 0 differing, 8 skipped
                              1588 of 1588 semantic assertions held
                              88 of 88 injected shapes held

  Add `pnpm corpus --exercise` if you touch the runtime join.
- **CORPUS REBASELINE NEEDS EXPLICIT APPROVAL.** If an expectation moves, stop and show the entry, the
  before, the after, and why the new value is correct. Do not record a new baseline on your own judgment.
  Note that `corpus.yaml` also holds hand-written `acceptance` blocks that `--record` does not touch.
- **Every fix gets a regression pin that is a REAL FALSIFIER.** Prove it: run the new test against the OLD
  behaviour and show it fails, then against the new and show it passes. A test that passes both ways is a
  **guard**, which is legitimate and required by AGENTS.md, but it must be labelled as one and never
  counted as a falsifier. The proven mechanism, used throughout this work:

      BASE=$(git rev-parse HEAD)
      git archive "$BASE" | tar -x -C /tmp/old-$BASE
      ln -s "$PWD/node_modules" /tmp/old-$BASE/node_modules
      # symlink each workspace @orchescope/<name> to the old tree's own copy, or the falsifier
      # silently tests the new source and passes both ways
      cp <new test> /tmp/old-$BASE/<same path>
      ( cd /tmp/old-$BASE && node --test <that path> )

- **Commits**: single line, imperative, no trailers of any kind, no AI authorship notice, no em dash
  characters anywhere in code, comments, docs or commit messages. Use:

      git -c core.hooksPath= -c user.name='Glendon Chin' -c user.email='glendonchin@gmail.com'

  Never use `gh pr merge`.
- **Land in separable commits with their own corpus gate**, so a genuine regression cannot hide inside a
  wide diff. This worked: defect B moved zero product expectations across 48 repositories, and that was
  only visible because it landed alone.
- Do not publish to npm. Do not tag. Do not touch the 0.9.2 release artifacts.
- Follow `docs/guides/release.md` and `docs/guides/pre-release-blind-evaluation.md`. A product fix
  invalidates a blind measurement, so no fix may be made during an evaluation. No evaluation is in
  progress at `ffa14b9`.

## Method that worked, and is worth repeating

The corpus cache at `corpus/.cache` is fully populated, so a candidate predicate can be **measured against
56 real repositories before any code is written**. Every good decision in this work came from that and
every bad one came from arguing instead. Two specific lessons:

- A 14-repository sample supported a change the full corpus refuted. **Measure over everything.**
- The pinned negatives are the canaries: `express`, `flask`, `axios`, `orchescope-discovery` (zero
  component ceiling), `open-agent-platform` (the ADR 0004 entry) and `llm-mock` (the acceptance negative
  control). If a widening moves any of them, it is wrong.

## Definition of done

A written design reviewed before code, the same discipline as last time. Then: layer 1 genuinely
framework-blind so no protocol reader is gated on a distribution name; a decision on the argument-less
construction that is either a working floor measured over the whole corpus or an explicit written refusal
with its evidence; the declaration forms either read or recorded as refused; every fix carrying a proven
falsifier; all gates green with real numbers reported; and a plain statement of what the tool still cannot
do and what would break the invariant.

Say what you did NOT fix and why.
