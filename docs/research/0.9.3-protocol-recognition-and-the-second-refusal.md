# Protocol recognition, and the second refusal of the floor

A design, written before any code, answering the seven items left in
[the handoff](0.9.3-remaining-work-handoff.md). Every number in it was measured against all 56 corpus
entries with this repository's own analyzer before a line was written. Where a measurement refuses a
proposal, the refusal is recorded with its numbers rather than the proposal being reshaped until it passes.

## The instrument, first, because every claim below rests on it

`corpus/.cache` was reduced to facts by production traversal, `collectFiles` with the `DEFAULT_CONFIG`
traversal options and `respectIgnoreFiles` on, followed by `analyzeFileSet`: 56 entries, 10,299 modules,
55.8 seconds, one JSON per entry. The shipped `findUnclaimedImportedConstructions` was then run over those
facts and reproduced production output exactly, so a candidate predicate could be measured beside the real
one rather than beside a copy of it.

**Baseline at `f4ecd89`:** the located refusal reader produces **145 areas on 23 of 56 entries**, and
**zero on all eight canaries** (`express`, `flask`, `axios`, `orchescope-discovery`, `open-agent-platform`,
`llm-mock`, `agentgauge`, `fenceline`).

## The verdicts, up front

| item | verdict |
| --- | --- |
| 1. MCP is gated on a three-entry distribution allowlist | **fix, in three parts**, one of which costs one component |
| 2. A construction with no arguments is silent | **refused again, with new evidence.** One narrow increment ships and is labelled as one |
| 3. Subclassing and decoration are invisible | **refused again, with new evidence** |
| 4. Annotations and re-exports were never built | see the section; measured separately and answered separately |
| 5. Layer 0 can be silent before any layer runs | **fix, but not the way the handoff proposed.** The honest fix is a number, not a language |
| 6. `langchain_core` is claimed by nobody | **fix**, and named as a claim-list correction because that is what it is |
| 7 and 8. Known limits and hygiene | see the sections |

Two of the seven are refusals. That is the intended shape: the brief asked for fewer of these done
correctly rather than all of them done in a way that has to be undone.

# 1. MCP: what the allowlist is actually doing, and which third of it is a defect

    packages/discovery/src/adapters/mcp.ts:38
    const SDK_PACKAGES = ['@modelcontextprotocol/sdk', 'mcp', 'fastmcp'];

That one array does three unrelated jobs, and conflating them is why it reads as a single defect.

| use | site | what it decides | is it a defect |
| --- | --- | --- | --- |
| applicability | `:479-481` `projectUses(context, SDK_PACKAGES)` | whether the MCP reader runs at all | **yes, and it is the worst of the three.** A fourth SDK's repository never reaches the reader |
| recognition | `:238` `matchCalls({ names, packages: SDK_PACKAGES })` | which constructions mint `mcp_server` | **yes**, and it is bound by ADR 0004 because it mints components |
| the claim | `:238` `packages: SDK_PACKAGES` on the adapter | who owns the name, for `adapter_found_nothing` against `unclaimed_imported_construction` | **an ownership table**, which the handoff already allows, but it should be **derived from the evidence** rather than maintained by hand |

## What the protocol makes visible in source, measured

The runtime shim recognises MCP from a JSON-RPC document (`packages/instrumentation/src/json-rpc.ts:24-28`).
Four candidate static analogues were measured over all 56 entries.

| signal | sites | entries | canaries |
| --- | --- | --- | --- |
| the specification's method names as bare word sets on a callee | 846 | 14 | `open-agent-platform` 3 |
| **anchored protocol call site**: the method word set **and** that method's own specification params | **22 direct, 37 reached through the anchored receiver** | **9** | `open-agent-platform` 2, both true |
| the `initialize` handshake: a `capabilities` object whose keys are specification capability nouns | 1 | 1 | 0 |
| the method names as literal strings in first-party source | 12 | 2 | 0 |

The bare word set is refuted: it names `pydantic-ai`'s own `self._call_tool` 121 times, `langgraph`'s
`ToolCall(name, args, id)` from `langchain_core.messages` 28 times, and `langgraphjs`'s `stream.toolCalls`.
Anchoring it to the method's published params removes every one of those, because `tools/call` carries
`{name, arguments}` and `_call_tool(tool_call_result)` carries nothing.

**The anchored form names the fourth SDK with no name in the predicate.** `session.call_tool(name=,
arguments=)` on `workflows-acp` is `tools/call` with its specification params, spelled in Python's naming
convention. `client.callTool({name, arguments})` on `mcp-filesystem-server` and `ollamaton` is the same
method spelled in JavaScript's. The derivation is the same word-splitting `segmentsOfKey`
(`unclaimed-imported-construction.ts:81-87`) already does for argument keys, applied to a method name and
matched against a vocabulary published in the MCP specification.

**This is the point on which the measurement disagreed with itself and the disagreement is worth stating.**
An independent measurement of the same question concluded that the SDK half is irreducibly name-shaped, on
the grounds that `listTools`/`call_tool` are camelCase and snake_case transliterations invented by the SDK
authors and published in no specification. That objection is right about a *list* of transliterations and
wrong about a *derivation*: the predicate here holds the published method path `tools/call`, splits it into
words, and asks whether a callee's words are that set and whether its arguments are that method's published
params. A fifth SDK spelling it `toolsCall`, `tool_call` or `callTools` matches without an edit. A method
named `_call_tool` that carries none of the params does not.

## The design

### 1a. Applicability from protocol evidence

`appliesTo` drops `projectUses(context, SDK_PACKAGES)` and asks instead for any of: an anchored protocol
call site, a construction carrying the `initialize` handshake capabilities shape, a server-entry shape
(`{command, args, env}` or `{url, headers}`) written in source, or the existing configuration-key test.

Measured: it reaches every entry that mints anything today, **plus** `crewai`, `gpt-researcher`,
`ollamaton`, `open-deep-research` and `workflows-acp`, and it **drops** `open-agent-platform`, which is a
correction in the canary's direction. Applicability mints nothing, so this half carries no ADR 0004 risk.

### 1b. Recognition from the protocol's own role vocabulary, confirmed by protocol evidence

A value is an MCP server when all three hold:

1. it is bound to a construction whose symbol is **type-shaped by the language's own naming convention**
   (a leading capital: PEP 8 and the JavaScript convention both spell a class this way) and whose words
   carry **the protocol's own name** (`mcp`) or are exactly the bare server role noun (`server`), and are
   not the other role (`client`);
2. the construction's specifier reaches a distribution rather than a file this repository writes, under
   the **narrow** provenance gate;
3. the value receives at least one registration, a call or a decorator, whose name carries one of the
   specification's **server** capability nouns (`tools`, `resources`, `prompts`, `logging`, `completions`).

Receivers are keyed by `(enclosing, name)`, which `receiverKey` (`mcp.ts:246`) already does.

**Measured: 19 servers on 8 of 56 entries, zero on all eight canaries, recovering 20 of the 21 baseline
sites.** `openai-agents-python` 6 of 6, `anthropic-quickstarts` 1 of 1, `mcp-filesystem-server` 1 of 1,
`openai-agents-js` 1 of 1 across its three twins, `pydantic-ai` 4 of 5.

Three variants were measured and refused:

- **without condition 3**, the construction alone: 139 sites on 9 entries. The content is `McpError`,
  `MCP` and `McpCapabilities`. It would mint 139 `mcp_server` components against 21 today.
- **without the type-name convention**: 25 on 8. It adds `dbosify_mcp_toolset` and
  `prefectify_mcp_toolset`, which are factory functions and not servers.
- **with the broad provenance gate**: all six `openai-agents-python` servers are lost, because that
  repository has `src/agents/mcp/` and `definedPackages` therefore claims `mcp` as first-party.
  `local-modules.ts:52-67` says in its own words why the broad set exists: "the two errors are not the
  same size, so the two readers do not share an answer." A layer 1 **recogniser** is a third reader and
  needs the narrow answer. That is a finding in its own right and it recurs below.

**Is `mcp` in a symbol a name in an array?** It is one word, and it is the protocol's own name rather than
any vendor's. `FastMCP`, `McpServer`, `MCPServer`, `FastMCP2` and `MyMcpServerBase` all match it without an
edit; `@modelcontextprotocol/sdk`, `mcp`, `fastmcp` and `mcp_use` are four vendor names and a fifth needs a
fifth entry. The distinction is real and it is also the weakest point in this design, so it is stated
plainly rather than buried: **if this reads as a name list to you, say so and I will ship 1a and 1c alone,
which cost nothing and remove the applicability gate, and leave `matchCalls` as it is with a header
recording why.**

### 1c. The claim, derived rather than maintained

`adapter.packages` stops being a constant. The distributions the MCP adapter claims for a repository are
the ones its own protocol evidence named: the origin of a recognised server construction, and the origin of
the receiver of an anchored protocol call site. `mcp_use` on `workflows-acp` then lands on
`adapter_found_nothing` rather than in the refusal list, and it does so because the repository showed the
protocol, not because anybody added a fourth string.

### What this costs, and the rebaseline it needs

**One component.** `pydantic-ai tests/test_mcp.py:127` constructs a `FastMCP` whose bound value carries no
capability registration in the same module, so condition 3 fails.

| entry | field | before | after | why |
| --- | --- | --- | --- | --- |
| `pydantic-ai` | `components.byKind.mcp_server` | 5 | 4 | `tests/test_mcp.py:127` is a bare `FastMCP` construction with no registration on the value it produced. Under the shipped predicate it is a server because the import came from a listed distribution; under the protocol predicate nothing in the source says it serves the protocol. The other four are recovered exactly. |
| `pydantic-ai-exercised` | same | 5 | 4 | the same site on the exercised twin |

**No other entry moves**, and the eight canaries are unchanged. `open-agent-platform` keeps 26 components
and `agentSystemDetected: false`: the two anchored protocol call sites there are true, and they mint
nothing by construction.

### What MCP recognition still cannot do

- **A protocol call site mints nothing, deliberately.** `mcp.callTool({name, version, arguments})` at
  `open-agent-platform apps/web/src/hooks/use-mcp.tsx:86` is a real MCP call in a repository pinned with no
  `mcp_server` key. Naming a server from a client call would need a server name the call does not carry,
  and inventing one is the widening ADR 0004 refuses.
- **A server whose SDK spells everything its own way, registers nothing recognisable, and never names a
  transport, is not recognised.** The specification defines a wire protocol and no source-level API. That
  boundary is now stated in the adapter's header instead of being implied by an array.
- **`mcpServers` and `servers` are not a published protocol vocabulary.** They are a configuration
  convention four host applications share and do not agree on, which the adapter's own header
  (`mcp.ts:26-29`) already admits. The whole configuration half rests on it. That is written down here
  because it was not written down anywhere before.

# 2. The argument-less construction: refused again, with new evidence

The handoff asked for a signal or a refusal, and said guessing is not an answer. This is a refusal, and
here is the evidence.

## The size of the silence, which belongs in the record whatever is decided

Over all 56 entries, every construction whose origin passes the shipped provenance gate, by argument shape:

| shape | sites |
| --- | --- |
| zero arguments | 5,502 |
| mixed, no object | 3,325 |
| string or number literals only | 3,062 |
| identifier or member only | 2,636 |
| an object argument carrying no entries | 141 |
| **silent total** | **14,666, on 50 of 56 entries, across 321 distributions** |
| carries an object argument, which the shipped net reads | 7,656 |

The silence is nearly twice the population the reader can see. The largest distributions in it are `zod`
6,035, `react` 1,921, `vitest` 491, `typescript` 433, `pydantic` 380, `pyqt6` 332, `drizzle-orm` 322,
`click` 314, `@orchescope/source-analysis` 305, `typing_extensions` 300, `streamlit` 246, `rich` 192.
`orchescope-discovery`, the zero-component-ceiling canary, holds 391 of them.

## The decisive number is a reach ceiling, not a canary count

Of the 14,666 silent sites, **11,453 carry no resolvable name at all**, and 5,502 of those have no
arguments, so no dataflow of any depth can reach them. **69 sites, 0.47 per cent, resolve to a local object
literal under a maximally permissive intra-module resolver.** Every candidate that reads *arguments* is
bounded above by 69 before precision is considered.

## Every candidate that reads names instead moves the canaries

| candidate | sites | entries | canary total |
| --- | --- | --- | --- |
| shipped stems on the constructed symbol name | 112 | 16 | **7** |
| shipped stems on the binding name | 185 | 20 | **20** |
| both | 280 | 23 | **27** |
| `agent` added, on the symbol name | 17 | - | **1** |
| `agent` added, on the binding name | 22 | - | **12** |
| the stem set derived mechanically from every `GEN_AI` constant | 1,487 | 44 | **22** |
| a silent construction in a module that also holds a model call | 3,223 | 33 | **164** |

The canary content is the argument. `llm-mock`, the 0.9.2 acceptance negative control, takes five hits, all
`express.Router -> modelsRouter` at `src/providers/*/routes/models.ts`. `open-agent-platform`, the ADR 0004
entry, takes three, all React hooks: `react.useMemo -> filteredTools`,
`react.useCallback -> checkPreSelectedTools`. `axios` takes `https-proxy-agent.HttpsProxyAgent`, the oldest
false friend the word `agent` has. Off the canaries it is the same disease: `rich.Prompt`, which is a
terminal input prompt, sixteen times.

**Why the position matters, stated as the reason rather than as an outcome.** An argument key is a slot in
somebody else's declared interface: `model=` means the callee accepts a model. A symbol name and a variable
name are free text an author chose, and `model`, `tool` and `prompt` are among the most overloaded words in
software: an HTTP route serving `/v1/models`, a Qt signal, a Zod schema, a pydantic data model, a terminal
prompt. The shipped stems are precise **because of where they are matched**. Moving them removes the only
thing that makes them provenance-shaped.

## The OpenTelemetry derivation, answered honestly

`packages/traces/src/attributes.ts:17-37` holds nineteen `GEN_AI` constants, including `gen_ai.agent.name`
and `gen_ai.agent.id`. `gen_ai.agent.description` is **not** there.

A mechanical derivation is possible and catastrophic: splitting all nineteen names yields twenty-eight
stems including `name`, `type`, `id`, `call` and `time`, which at the shipped argument-key position produce
**1,487 new sites on 44 entries with 22 canary hits**, among them
`flask src/flask/cli.py:517 click.Option key=type` and
`open-agent-platform apps/web/src/lib/agent-utils.ts:150 react.createElement key=className`.

And the derivation **cannot produce `llm` or `instruction`**, two of the five stems that ship. You cannot
claim the stems come from the standards body and keep the stems you have. **The provenance argument for
`agent` is a rationalisation and is refused as one.** What was actually being proposed is
`MODEL_STEMS.push('agent')`: a name added to an array.

For completeness, because it is the only widening that keeps every canary at zero: `agent` at the shipped
**argument-key** position gives 48 sites on 8 entries with canary total 0, and names `vertexai.AdkApp`,
`google.AgentTool`, `@mastra/core.Mastra` and `autogen.GroupChat`. **It is still refused**, because 33 of
the 48 are one file of Zod schemas at `openai-agents-js packages/agents-core/src/runState.ts:188-228` and
the honest precision is 31 per cent. It is a name in an array and the brief was explicit about those.

## What does ship, and it is an increment rather than a floor

**N6, the argument bridge.** An identifier, member or keyword-bundle argument is resolved through
`DefinitionFact.value` / `AssignmentFact.value` and the **shipped** `constructionRole` predicate is applied
to the result unchanged. No new vocabulary, no new resolver: `resolveSourceValue`
(`packages/discovery/src/source-value.ts:304`) already walks exactly this chain with a four-hop bound,
before-use ordering and a uniqueness requirement, and `prompt-settlement.ts` and
`source-dataclass-default.ts` already trust it.

Discipline decides most of the result, and the loose form is provably wrong:

| variant | sites | entries | canaries |
| --- | --- | --- | --- |
| last binding in scope, any line, any branch | 26 | 6 | 0 |
| the binding must be written before the call | 17 | 5 | 0 |
| **before the call, and unconditional or on the call's own branch** | **10** | **4** | **0** |

The loose form hands all fourteen `gpt-researcher` sites `model_id` from
`gpt_researcher/llm_provider/generic/base.py:233`, a Bedrock branch mutually exclusive with the Anthropic
branch that made the call at `:164`. That is the "name an owner that is not the owner" failure
`boundReceivers` already records in its own comment (`unclaimed-imported-construction.ts:311-318`).

**Shipped form: 10 sites, 4 corpus entries, 2 distinct repositories, 2 newly named distributions, zero
canaries, and no entry gains its first refusal**, so `scanPopulationComplete` moves nowhere new.

- `crewai lib/crewai/src/crewai/rag/embeddings/providers/ibm/embedding_callable.py:157`,
  `watson_models.Embeddings(**embeddings_config)` where `:60` binds `{"model_id": ...}` unconditionally.
  It names `ibm_watsonx_ai`, which nothing else in this build names.
- `openai-agents-js integration-tests/{bun,deno,cloudflare-workers/worker/src}/…`, `aisdk(fakeModel)` where
  `fakeModel` is a module-scope object carrying `modelId`. It names `@openai/agents-extensions`.

**It closes 0.07 per cent of the gap, and that sentence belongs beside the number every time it is
reported.** The second dataflow hop was measured and refused on its own evidence: 10 sites with a 40 per
cent wrong-owner rate, including `json_repair.loads` reported because
`response = create_chat_completion(model=...)`.

## The refusal, stated for the record

**The invariant remains held in a weaker form than its literal statement, and this is the second whole-corpus
measurement to say so.** A construction whose arguments name a model, a tool or a prompt cannot go silent;
one whose arguments are opaque, or absent, still can. Nothing separates `create_agent(config)` from
`make_widget(config)` structurally, for the same reason ADR 0014 gives about base classes: a factory call
with one opaque argument is how every library is called.

# 3. Subclassing and decoration: refused again, with new evidence

The baseline was reproduced independently: N2 and N3 move **26 of 48 entries**, 1,994 sites, 40
distributions, dominated by `pydantic` 1,079, `typing_extensions` 472 and `click` 161. It also moves a
canary the ADR did not name: **`flask`, 33 sites**.

Seven separating candidates were measured over the whole corpus, including three the handoff did not name.
The pinned target is `workflows-acp src/workflows_acp/workflow.py:18 class AgentWorkflow(Workflow)` with
`@step` at `:34, :49, :61, :83, :106`.

| candidate | entries of 48 | sites | `flask` | target kept |
| --- | --- | --- | --- | --- |
| behaviour rather than fields | 18 | 887 | **31** | yes |
| the members reach a layer 1 or layer 2 recognition | 7 | 16 | 0 | **no** |
| co-occurrence, module scope | 7 | 104 | 0 | **no** |
| co-occurrence, repository scope | 16 | 1,840 | 0 | yes |
| the base is itself constructed with stems | 0 | 0 | 0 | no |
| decorator arity | 13 | 481 | **15** | no |
| decorator with a stem argument | 0 | 0 | 0 | no |
| a stem-bearing call in the body, and a stem-bearing member parameter | **5** | **24** | 0 | **yes** |

**The behaviour-versus-fields intuition is refuted by nested intervals, not by a close call.**
`typing_extensions.TypedDict` has 349 sites, all with zero methods; `workflows.Event` has 4 sites, all with
zero methods and one to two fields. `pyqt6.QWidget` has 12 sites with 2 to 28 methods; `workflows.Workflow`
has 1 site with 6 methods. `pydantic.BaseModel`'s 803 sites span 0 to 88 methods, which covers the entire
signal range.

**The last candidate passes the stated bar and is still refused, on three grounds.**

1. **It is not a separator.** Strip the base class and the decorator from it and the surviving evidence is
   unchanged: a call in a lexical range whose argument names carry a stem, which is `constructionRole`
   evaluated over an enclosing scope. One predicate wearing two scopes is not two kinds of evidence.
2. **It names the wrong owner on 19 of the 24 sites it keeps**: `pydantic` 10, `typing_extensions` 9. A
   reader is told `pydantic.BaseModel is subclassed at lib/crewai/src/crewai/crew.py:159 and no adapter
   claims that distribution` when the unread thing on that line is `Crew`.
3. **The counterexample is inside the target repository.**
   `src/workflows_acp/events.py:24 class PromptEvent(Event): prompt: str` and
   `packages/.../api/shared.py:64 class TaskRequest(BaseModel): prompt: str` have identical feature vectors
   on all seven measured features. One is the declaration form the ADR wants read; the other is a FastAPI
   request body.

**The whole-corpus statistic.** Labelling every site by the kind of library that owns its declaration form,
over 82 agent-framework sites and 1,782 others: 19 of the 25 structural signatures the framework group
occupies are also occupied by the noise group, and **72 of the 82 framework sites sit on a shared
signature**. The largest shared signature holds 33 framework sites and 642 others.

**ADR 0014's sentence stands and this is the second measurement to say so.** A base class and a decorator
remain how every library asks for a declaration.

## A side finding that must be recorded: `CallKind = 'decorator'` is dead

`packages/source-analysis/src/facts.ts:99` declares it. Across 56 repositories there are 720,172 calls of
kind `call`, 38,909 of kind `new`, and **zero** of kind `decorator`. A bare `@step` and a called
`@DBOS.dbos_class()` reduce to the same fact with `args: []`. Any future work that needs the two
distinguished needs a new fact, not a new predicate. This is reported, not fixed.

# 4. Re-exports and annotations: one is a correction, the other is refused

The two were measured separately because they are different in kind, and they got different answers.

## The re-export bridge: build it, and state that its yield is zero

Today the build asserts that `np`, `Popover` and `RunStartParams` are names this repository owns. That
assertion is false, and correcting it can only make the ownership answer more right. ADR 0014 decision 1
already **states as accepted** that "Re-exports are followed: a local specifier is resolved to the module it
names and that module's imports are asked where the symbol came from." That sentence is not true of the
code. Either the bridge is built or the record is amended, and the bridge is about thirty lines.

Measured over all 56 entries. Of **30,293** specifiers refused as local for a local reason:

| terminal state | count |
| --- | --- |
| genuinely this repository's own name | 18,937 |
| exported but the binding is unreadable | 6,327 |
| the specifier resolves to no analysed file | 4,832 |
| a namespace import, unanswerable | 93 |
| **a re-export cycle** | **31** |
| **reaches an unclaimed distribution** | **36** |
| **reaches a claimed distribution** | **37** |

**New refusals produced: zero. Entries moved: zero. Canary movement: zero on all eight**, in the baseline
and in both counterfactuals where the analyzer's own holes are closed. All 440 chain-resolved call sites
fail the shipped argument-name test. Adapter applicability changes on no entry.

What it fixes is 36 wrong ownership claims, 13 of them value imports:
`openai-agents-python src/agents/voice/events.py:6` imports `np` from `.imports`, which imports it from
`numpy`; `vercel-ai-chatbot components/ai-elements/model-selector.tsx:14` imports `Popover` from
`@/components/ui/popover`, which imports it from `radix-ui`.

**ADR 0014's premise needs correcting in the same breath.** "Wrapping a third-party library in an internal
module is the most common production shape there is" is true about wrapping and false about this bridge:
the bridge fires only on **re-exporting the third party's own symbol under its own name**, which is 36 of
30,293 refused-local specifiers, 0.12 per cent. 1,396 repository modules do wrap a foreign symbol; only 13
value imports reach one through the wrapper.

Four conditions on building it, each from the measurement:

1. **`resolveSpecifier` must be exported from `symbol-index.ts:149-154` and reused.** It is a closure inside
   `buildSymbolIndex` today. Neither `resolve` (`:156-174`, which stops at a `DefinitionFact` and discards
   the terminal package) nor `external` (`:176-183`, one hop from the file you ask about) answers the
   question. Proved on the one real Python shim in the corpus: `resolve('src/agents/voice/events.py','np')`
   is `undefined`, and so is `external` on the same file, while `external('src/agents/voice/imports.py','np')`
   returns `{module: 'numpy'}` if you already knew which file to ask.
2. **Carry an explicit visited set.** **30 real re-export cycles** exist, all Python `from . import X` in a
   package `__init__.py`, including `flask src/flask/__init__.py:1`. The shipped `resolve` has no visited
   set and terminates on them only by burning hops, so "cycle" and "gave up" are indistinguishable today.
3. **The falsifier is a fixture, not a corpus entry**, because nothing in the corpus moves.
4. **Name the latent cost.** The bridge makes 162 call sites newly *eligible* for the argument test, 156 of
   them `logger.debug` on the `debug` package in `openai-agents-js`. They pass nothing today, and any
   future loosening of the stem lists inherits them.

Cost: 24,391 chain walks over the whole corpus in 459 ms, about 8 ms per repository. `MAX_HOPS = 4`
(`symbol-index.ts:35`) is already twice the deepest chain observed, which is 2.

**Two adjacent analyzer defects it exposed, recorded and not fixed here.** The JavaScript analyzer discards
the source module of `export { X } from "spec"`: `javascript/analyze.ts:370` does not declare
`moduleRequest` on `staticExports` and `:394-397` records only the name, so **1,083 real re-export bindings
in the corpus are unreadable**. Closing that recovers 2,018 chains and still produces zero new areas, so it
is a fact-model correctness fix rather than a coverage fix. And `resolvePython` (`symbol-index.ts:109-133`)

# 5. Layer 0: the honest fix is a number, not a language

`LANGUAGE_MARKERS` (`discover.ts:116-125`) is an eight-entry extension table. Two findings change what the
fix should be.

**It is dead code on this corpus.** **0 of 56 entries** carry a `.go`, `.rs`, `.java`, `.kt`, `.kts`,
`.swift`, `.cs`, `.rb` or `.php` file, confirmed twice: once from production `extensionCounts` and once
from a raw `find` over `corpus/.cache` ignoring every traversal exclusion. All 57 recorded observations in
`corpus/expected/` carry `languagesNotAnalysed: []`. **No change to that table can be validated by the
corpus gate in either direction**, and that fact has to be stated before any proposal is weighed.

**The real silence is much larger than the table's subject.** Across the corpus, 43,000 paths are walked and
14,667 are recorded in any form. **28,333 paths, 65.9 per cent, are never recorded at all, on 55 of 56
entries.** Of the 27,767 that carry an extension: markup and documentation 26,482 (95.4 per cent), binary
assets 704, **source code 330 (1.2 per cent)**, generated output 128, data 123.

## Every shape-based replacement was measured and refused

| rule | entries | rows | precision | canaries |
| --- | --- | --- | --- | --- |
| an extension with N or more unread files, best N | 32 | 92 | **17.4 per cent** | 6 of 8 |
| the same, canary-free | requires N of 200, at which the rule sees nothing | | 0 | 0 |
| text that does not parse as data | 55 | 291 | 13.1 per cent | 7 of 8 |
| content shape, best single axis | | | | |

**There is no knee in the threshold curve.** Precision peaks at 17.4 per cent and reaches zero before the
canaries fall silent, because noise and signal decay at the same rate: raising the threshold kills `.sh`,
median four files per entry, before it kills `.md`, median six.

**"Does not parse as data" has the sign backwards.** The only format-blind data test available is JSON,
because JSON has one grammar and a parser in the runtime. Its whole effect is to delete **139 Jupyter
notebooks**, the largest block of executable source in the unread set. YAML is not a data test: it accepts
360 Markdown files, 122 SVGs and every zero-byte `py.typed`.

**Content shape does not separate `.md` from `.go`.** Measured against 2,998 real Go standard-library files
and 2,982 real Rust files, the best single axis catches 71.8 per cent of Go against 11.0 per cent of
Markdown, the direction is the opposite of intuition (source has *shorter* lines than prose), and the shape
of "source" moves 75 per cent depending on which Go files are sampled. The only precise content signal, a
shebang, is a self-declaration rather than a shape: it sees 100 per cent of shell and **0 of 2,998 Go
files**, and it still moves `flask`.

**A manifest table is a vendor name list and the rename does not launder it.** The gates that shipped are
provenance because the runtime being asked produces the list: `builtinModules` comes from the Node process
actually running, `sys.stdlib_module_names` from the Python that owns the package, `ROOT_ALIASES` from the
bundler configuration the repository itself wrote. **`go.mod` cannot be asked of anything, because no Go
runtime is present during a scan.** `{'go.mod': 'go', 'mix.exs': 'elixir'}` differs from `LANGUAGE_MARKERS`
only in which string it matches and a ninth ecosystem needs a ninth entry in exactly the same way.

# What I am not fixing, and why

**Refused on measurement, each with its numbers above.**

- **The argument-less floor.** 14,666 silent sites on 50 of 56 entries, a reach ceiling of 0.47 per cent,
  and canary counts of 7, 20, 27, 22 and 164 for the five families of alternative.
- **Subclassing and decoration.** 72 of 82 agent-framework declaration sites share a structural signature
  with data models, GUI widgets, command-line decorators and type-system declarations, and the
  counterexample is two files apart inside the target repository itself.
- **`agent` as a sixth stem.** A name in an array. Its provenance argument does not survive contact with
  `attributes.ts`, which holds neither `llm` nor `instruction`, and its honest precision is 31 per cent.
- **Naming an unread language.** Every candidate is a table this build maintains, and no runtime present at
  scan time can be asked instead. The count ships and the name does not.
- **The annotation net.** Two thirds of it is not representable in the fact model, the buildable third is
  Python-only, it moves `flask` 11 times, and its one canary-clean form is worth four sites of which one
  names a distribution nothing else in the corpus names.
- **Claiming `langchain_core` as a distribution**, and a `name_` arm in `moduleMatches`, which would hand
  `ai_article_writer_master` to the Vercel `ai` SDK and `mcp_use` to `mcp`.

**Recorded and not fixed, because each is larger than this change.**

- **`namesDefinedPackage` over-claiming.** It reports `dbos`, `prefect` and `mcp` as first-party on
  repositories that merely have directories of those names. Section 1b bounds it for layer 1 by using the
  narrow gate; narrowing it generally means arguing the cost-of-error question that `local-modules.ts:52-67`
  already argues for two readers, for a third.
- **`CallKind = 'decorator'` is dead.** Declared at `facts.ts:99`, produced zero times in 759,081 calls
  across 56 repositories. Removing it or producing it are both larger than this change, and any future work
  that needs `@step` distinguished from `@mcp.tool()` needs a new fact rather than a new predicate.
- **The JavaScript analyzer discards the source module of `export { X } from "spec"`**, which makes 1,083
  real re-export bindings unreadable. Closing it produces zero new areas, so it is a fact-model correctness
  fix with no coverage consequence.
- **`resolvePython` is narrower than `namesDefinedPackage`**, so 3,668 Python specifiers are refused as
  local by a broad rule and then cannot be resolved by a narrow one.
- **One table with one row per component kind and one column per facet**, replacing eight populations. It is
  the right larger change and it is a refactor of eight argued decisions, not a fix.
- **The current membership of the eight kind-keyed populations.** `OBSERVABLE_KINDS` omitting `provider` and
  `prompt`, and `REACHABILITY_KINDS` omitting `model` and `provider`, are argued in their own headers and
  are preserved unexamined.

**Needs your decision before it is touched.**

- **`schemas/manifest.v1.json` and `manifest.v2.json`.** Delete or emit. Both change a published artefact.
  I recommend deleting.
- **The `promptsAdapter` claim.** It fixes a provable self-contradiction and costs eight areas across eight
  entries, three of which flip `scanPopulationComplete`, and one of which has a live `topology-shape`
  finding that must be re-measured.
- **The `mcp` word in a symbol.** If it reads as a name list to you, sections 1a and 1c ship alone, the
  applicability gate is still removed, and `matchCalls` keeps its distribution list with a header recording
  why.

**Unchanged and still true.** `tiny-code`'s local dispatch table, Ollama's native operations, a streamed or
protobuf request with no readable model field, and a repository declaring one model id under two providers.
