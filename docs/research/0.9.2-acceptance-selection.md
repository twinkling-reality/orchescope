## Exclusion clearance

Excluded populations, enumerated before selection:
- every `source: git` pin in `corpus/corpus.yaml` (49 entries) and every `source: local` path;
- every repository URL, owner and revision named anywhere in `docs/research/*.md`, including the
  0.9.1 acceptance holdouts (`danindiana/smol-jobscout`, `lucas-albers-lz4/token-usage`) and the
  fdb11aa passing pair (`Dmitry9/docent`, `heswithme/claude-usage-analyzer`);
- 83 distinct `owner/repo` references extracted from docs, corpus, README, CHANGELOG, AGENTS,
  PLANS, tests, packages, apps and scripts.

Each selected lineage was searched for in: the tracked working tree, `corpus/corpus.yaml`,
`corpus/expected`, `docs/`, `schemas/`, `scripts/`, `tests/`, `packages/`, `apps/`, and the complete
reachable Git history (`git log --all -S<term>`, `git log --all --grep`, and a blob search across
`git rev-list --all`). Result: zero occurrences of any selected owner, repository name, URL, commit
or tree.

**One disclosure.** `docs/research/competitive-boundary.md:13` names "Mastra Studio" in a table of
competing *products* under "a local browser workspace showing agent runs". That is a market
reference to `mastra-ai`'s own studio UI. It is not a repository lineage, not a URL, not a revision,
not a corpus pin, and carries no expected answer. The selected target `laoposkj/mastra-agentic-rag`
is a third-party application, unrelated to that mention and absent everywhere. Selection proceeds,
with the mention recorded here so the release owner can weigh it rather than discover it.

## Predictions recorded before measurement

Recorded so that a matching result is a confirmation rather than a story told afterwards. These are
hypotheses from reading Orchescope's own published logic, not from reading any target's source.

- `packages/discovery/src/unclaimed-imported-construction.ts` recognises an unread construction only
  when an object argument carries a tools-shaped key (`tools`, `toolset`, `toolsets`,
  `managed_agents`) **and** a model-shaped key (`model`, `llm`, `language_model`, `chat_model`,
  `llm_config`). AutoGen's `AssistantAgent` takes `model_client=`, which is on neither list.
  **Prediction: T1 produces no finding and no bounded refusal a silent false negative.**
- Google ADK and LlamaIndex use `model=`/`llm=` with `tools=`, so T3 and T4 should at least reach
  `unclaimed_imported_construction`.
- A hand-written agent passes JSON tool schemas to a chat-completions call, which
  `toolsArgumentLooksLikeJsonSchemas` explicitly excludes. **Prediction: T5, T6, T7 produce no
  agent and no refusal.**
- Orchescope recognises a model call by provider host. `127.0.0.1:11434` is not in
  `BY_HOST_SUFFIX`, so Ollama traffic should arrive as an outside effect rather than a model.
  Whether that is reported as a boundary or silently is the question.
- T8 must report `agentSystemDetected: false`.
