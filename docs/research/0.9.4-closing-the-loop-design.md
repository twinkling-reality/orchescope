# Closing the loop: a design for the three remaining defects

A design, written before any code, for the three items
[the handoff](0.9.4-remaining-work-handoff.md) names as standing between this product and its own claim.
Every claim below was verified against source, measured in this working tree at `8d4202b`, or produced by
running the product. Each carries its `file:line` or the command behind it. Numbers from earlier
measurements are cited rather than re-derived.

**What was built, and where it differs from this design.** Item 1's Option C, item 2's 2b and the
skipped-evaluator fix were approved and are implemented;
[ADR 0016](../architecture/adr/0016-two-proofs-of-a-source-location.md) records the decision as it
actually shipped. Two things changed under contact with the code. The content proof is a **separate
field** rather than a widening of `ObservedSourceIdentity`, because relaxing that type's required fields
would have changed what an `ObservedSource` means to every reader of a stored document; as two optional
fields it needs no version bump and no migration, and the weaker claim cannot be mistaken for the
stronger one. And the producer selects a frame by asking whether the repository **tracks** the file rather
than by containment plus a `node_modules` exclusion, because containment was measured to lose the corpus's
only `code_location` joins and to emit the wrong path shape for a `subpath` entry. Everything else below
is as designed.

**Read the handoff first.** This document does not repeat what it settled. It records what changed once
each item was traced through the code that has to change, and then adversarially checked. Three traces
moved the work, and one of them refutes an instruction in the handoff itself.

## The short version

| item | the handoff's scope | what the code and the corpus say it is |
| --- | --- | --- |
| 1. source identity | promote a prototype, relax its git gates to **"is this path under the audit root"** | **that rule is refuted by the only `code_location` joins the corpus has.** They span two repositories at two revisions, produced by one traced run whose audit root is one of them. Containment loses that join. The rule that works is the prototype's: the repository that *tracks* the file. What has to go is the pinning, not the discovery. |
| 2. the goal flag | add `--goal` to the printed compare command | the flag is necessary and nowhere near sufficient. **Eight verified defects**, one of which makes the plan bank two criteria as satisfied on a comparison of a run with itself. |
| 3. a real scenario | write a scenario an operator can write | eligibility is a **static read of the YAML**, so a four-line unrunnable file flips it. The operator path exists and breaks in four measured places, one of which makes editing a scenario silently do nothing. |

Ten claims in documents this repository already published are wrong or rounded, recorded in
[What the tracing corrected](#what-the-tracing-corrected).

## Item 1: a source-identity producer

### D1. Which frame the producer selects

> **A frame qualifies when the repository containing its file *tracks* that file. The producer takes the
> deepest such frame within a bounded walk.**

Not "under the audit root". That rule was tested and it fails on the one measurement this feature would be
judged by, twice over.

**It loses the corpus's only `code_location` joins.**
`corpus/expected/openai-agents-js-filesystem-mcp.federation.json` holds them, and they span two checkouts
at two revisions: `https://github.com/modelcontextprotocol/servers` at `3e805376...` and
`https://github.com/openai/openai-agents-js` at `52b2702f...`, both confirmed on disk. The trace that
produced them ran with a single audit root, `openai-agents-js`
(`scripts/corpus/federation.mjs:97-112`, `scripts/corpus/exercise.mjs:139`), and the MCP server it spawns
inherits the shim through `NODE_OPTIONS`. The `read_text_file` frame lives in the other checkout. A
producer that refuses frames outside the audit root drops that join; one that stamps the audit root's
identity onto it attributes one vendor's code to another at the wrong revision.

**It emits the wrong path shape for a monorepo subpath.** `corpus.yaml:292-296` pins
`mcp-filesystem-server` with `subpath: src/filesystem`, and `scripts/corpus/checkout.mjs:47-60` makes the
audit root that subdirectory. The consumer strips `git.repositoryPath`, which is `src/filesystem`
(`packages/workspace/src/git.ts:116-135`), from the **observed** path to recover a scan-root-relative one
(`packages/graph/src/source-match.ts:84-96`). A path computed relative to the audit root arrives as
`index.ts`, does not start with `src/filesystem/`, and every join is refused `source_not_declared`.

**The tracked-file test is the rule, and it replaces a name list rather than adding one.** Ask the
repository containing the frame whether the file is in its index. That single question excludes
`node_modules`, `dist`, `.venv`, `__pycache__` and every other derived directory *without naming any of
them*, because they are gitignored. It is also the only gate that rejects the false attribution the corpus
already contains: for 14 of the 69 directories under `corpus/.cache`, `git rev-parse --show-toplevel`
answers the enclosing **orchescope** repository, and three of the prototype's four gates confirm that false
identity. `corpus/.cache` is gitignored (`.gitignore:26`) and `git ls-files corpus/.cache` returns nothing,
so the tracked test is what refuses it.

**Measured populations.** Every one of the 55 real checkouts has zero untracked-and-not-ignored files. This
repository holds 219 `node_modules` directories outside `corpus/.cache`, 218 nested deeper than one level,
at depths 3, 4, 6, 7, 8 and 10; none is tracked.
`corpus/.cache/mcp-filesystem-server/src/filesystem/dist/index.js` is real build output under an entry root
and is untracked, so the tracked test rejects it where a containment rule would not.

**Cost, and the one optimisation that would add a name.** The test is two subprocesses per *new* file:
`git rev-parse --show-toplevel` memoised per directory, `git ls-files --error-unmatch` memoised per file.
Distinct model-call sites in a repository are few, so the first capture from a site pays and the rest are
free. If measurement says that first-capture cost is unacceptable, a `node_modules` pre-filter avoids the
subprocess on frames that cannot qualify. **That name ships only if measurement forces it**, and if it
does, it lands with a test proving it changes no answer, because it is an optimisation and not the rule.

**What the rule does not solve, and is not pretended to.**

- A repository that **commits** its build output. Those frames name real tracked files that no declaration
  was read from, because the traversal skipped them (`packages/source-analysis/src/file-set.ts:86-117`).
- A **vendored** framework: the application's own file is strictly interior, four framework frames below it
  and the entry point above, all six tracked
  (`0.9.4-what-source-attribution-actually-buys.md:82-87`). Measured as rare, not otherwise bounded.
- A repository that is **not a git checkout at all** gets no pinned identity. D6 is what gives it one.

### D2. The bound

> **Twenty frames.** A ceiling on work, not a selection rule.

Limit 5 reaches the repository frame in 1 of 4 measured Node stacks, limit 10 in 2 of 4, limit 20 in 4 of
4, including `ai` over `@ai-sdk/openai` at index 16 and `@openai/agents` at index 13
(`0.9.4-repository-frame-depth.md:24-38`). The producer walks outward from the transport and stops at the
first qualifying frame, or at twenty, whichever comes first. Nothing says "the caller is frame N".

**The walk was run before it was written down.** A fixture with a repository root, a three-layer fake SDK
under `node_modules`, and a fourth dependency reached through a pnpm symlink:

    idx  under root  node_modules  path
     0   no          no            <the harness>
     1   yes         yes           node_modules/.pnpm/fakedeep@1/node_modules/fakedeep/index.mjs
     2   yes         yes           node_modules/fakesdk/index.mjs
     3   yes         yes           node_modules/fakesdk/index.mjs
     4   yes         yes           node_modules/fakesdk/index.mjs
     5   yes         no            src/orchestrator.mjs      <- selected
     6   yes         no            src/main.mjs
     7   no          no            <the harness>

It returns `{ file: 'src/orchestrator.mjs', line: 2, fn: 'askTheModel' }`: the deepest repository frame,
not the entry point above it. Frame 1 is the pnpm case, whose real path carries **two** `node_modules`
segments where the path Node was given carried one. All four excluded frames are also untracked, which is
why D1's test subsumes this and the segment check is only ever an optimisation.

### D3. The capture API

> **`util.getCallSites(20)`, not `Error.captureStackTrace`.**

`Error.captureStackTrace` is cheaper, 9,187 to 9,376 nanoseconds at limit 20 across depths 20 to 200
(`0.9.4-stack-capture-cost.md:22-30`) against 13,548 to 16,346 for `getCallSites`
(`0.9.4-what-source-attribution-actually-buys.md:24-31`). It also requires overriding
`Error.prepareStackTrace` and `Error.stackTraceLimit`, both process-wide and both the target's.

`getCallSites` touches neither. Verified on `node v24.15.0` here: a sentinel `Error.prepareStackTrace` and
an `Error.stackTraceLimit` of 3 both survive a `getCallSites(20, { sourceMap: true })` call unchanged. That
closes the hazard `0.9.4-stack-capture-cost.md` flagged rather than managing it, in a package whose rule is
that "the request happens exactly as it would have"
(`packages/instrumentation/src/outbound-fetch.ts:17-21`).

Its `scriptName` is a `file:` URL for ESM and a bare path for CJS, so the prototype's whole normalisation
(`corpus/instrumentation/node_source_identity.mjs:68-91`: `fileURLToPath`, a scheme guard, `realpathSync`,
`statSync().isFile()`) is carried over rather than reduced to a `startsWith`.

There is **no memory figure for `getCallSites` anywhere**. The 24.7 bytes per capture at limit 20 is an
`Error.captureStackTrace` figure. `getCallSites` returns `CallSite` objects, so allocation is measured
before the default is turned on.

### D4. Source maps stay off

A further 30 per cent, priced at exactly one bound: 21,655 against 16,659 at limit 20
(`0.9.4-what-source-attribution-actually-buys.md:35-36`). Of the 11 built corpus packages holding a model
call, **zero ship a runtime source map**. The option is off and the limit is stated in the module header.

### D5. Two roots, because the two proofs need different ones

The producer needs the **repository root**, discovered from the frame, for the pinned proof; and the
**audit root**, passed in, for the unpinned one. Neither substitutes for the other.

- **Repository root, discovered.** Required by federation, which joins frames from checkouts the audit root
  does not contain, and by `subpath`, where the consumer wants git-root-relative paths.
- **Audit root, passed as `ORCHESCOPE_REPOSITORY_ROOT` from `buildTargetEnv`.** Required by the unpinned
  proof (D6), whose path is scan-root relative and whose validity is confined to this workspace.

**Never `process.cwd()`**, for two independently demonstrated reasons. A scenario's `target.cwd` may be any
subdirectory (`packages/scenarios/src/run.ts:91-106,231`). And `NODE_OPTIONS` is inherited by every
descendant, so the shim installs into grandchildren whose cwd is arbitrary; a probe mirroring
`register.ts:21` produced one traced run with two shim installations at two different cwds. Every allowed
runner (`packages/runtime/src/shim.ts:23-43` admits `npm`, `pnpm`, `yarn`, `bun`, `deno`) spawns the real
target as a child, so this is the normal case rather than an edge one. `TARGET_ENV` declares sixteen names
and none is a path to a repository (`packages/schema/src/target-result.ts:47-65`).

**The prototype's gates are not corpus-specific.** Three of its four mirror consumer gates exactly: a
40-hex HEAD (`packages/traces/src/source-identity.ts:214-217`), a credential-free http(s) remote
(`:58-72`), and a clean tree (`packages/graph/src/source-match.ts:77-82`). The fourth, the tracked-file
test, is D1 and is load-bearing for correctness. What is corpus-specific is not the gates but the
*population*: `scripts/corpus/checkout.mjs:69-79` runs `git init`, `remote add origin`, `fetch --depth 1`
and `checkout --force --detach` before every audit, so all 55 checkouts are shallow, detached and clean.
The corpus manufactures every condition the gates test and measures none of them against a tree a person
edits. A larger sample would not have helped.

### D6. What it emits

Two consumer facts decide this.

**A refused source identity forfeits the name fallback.** `packages/graph/src/reconcile.ts:224` short
circuits to the source path and never falls through to `runtime_name`, `kind_and_name` or the bare-name
rule. **This is deliberate**: `packages/graph/test/graph.test.ts:1299` and `:1327` assert it by name, and
the reasoning is right, because a wrong revision or a different remote means the run was about different
code.

But that is a reason to refuse *those* refusals, not all five
(`packages/graph/src/source-match.ts:74,80,94,106,129,134`):

| refusal | what it says | fall back? |
| --- | --- | --- |
| `repository_mismatch` | a different repository | **no** |
| `revision_mismatch` | a different revision, or a dirty tree | **no** |
| `source_not_declared` | this tree, this file, no declaration of that kind and name in it | **yes** |
| `line_outside_declaration` | right file, the line missed a declared range | **yes** |
| `ambiguous_source_mapping` | two declarations match, the ambiguity the location existed to break | **no** |

> **Decision: a source refusal falls back to the name rules only when it does not say the run was about
> different code.** Both existing tests keep passing, because both use a reason in the **no** class.

**A dirty tree disables `code_location` entirely**, at `source-match.ts:77-82`, and the obvious escape is
closed: `packages/traces/src/source-identity.ts:171-178` takes the legacy branch only when
`code.file.path` is relative, so an absolute path without the `vcs.*` pair yields nothing at all.

Three options.

**Option A, promote the prototype unchanged.** Works where the corpus works, which is where a harness ran
`checkout --force --detach` first. Adds nothing for a working tree. Cheapest, no schema change.

**Option B, pinned when pinned, relative otherwise.** Adds a repository-relative `code.file.path` when the
checkout is not pinned, so a runtime-only component gets a real `sourceLocations` entry
(`packages/graph/src/reconcile.ts:450-458`) and never joins. Every population gets something. No schema
change. Still no join on a dirty tree.

**Option C, recommended: a second proof, by content.** The evidence already exists on the declared side.
Every declared `SourceLocation` carries `fileHash`, the sha256 of the file at scan time
(`packages/schema/src/evidence.ts:41-42`), stamped at `packages/graph/src/graph-builder.ts:112-116`, whose
comment says "The digest is what makes staleness detectable per file rather than per scan". Verified in a
live store: a component carries `{"file":"src/agents/workers.ts","startLine":1,"fileHash":"c04240bc..."}`.

So the matcher accepts a location on **either**

- the **pinned** proof: canonical remote, 40-hex revision, git-root-relative file. Unchanged, and the only
  proof federation uses (`packages/graph/src/federate.ts:229` calls the matcher on its own). This is the
  proof that carries the cross-repository joins D1 exists to preserve.
- the **unpinned** proof: the frame's repository root is the audit root, the path is scan-root relative,
  and the observed digest equals the declared location's `fileHash`.

Both prove the proposition ADR 0007 needs: *the file the run pointed at is the file the declaration was
read from*. The revision check proves it indirectly and only on a clean tree; the digest proves it
directly, and a reader can check it with `sha256sum`. That the two halves are the same tree is not
inferred: runs and scans are listed by `workspace.projectId` (`packages/usecases/src/audit.ts:148`) and a
project id is minted from the scan root (`packages/discovery/src/discover.ts:869-870`). A digest mismatch
joins the **no** class above: it says the file changed between the run and the scan.

Costs:

- One schema document changes. `ObservedSourceIdentity`
  (`packages/schema/src/runtime-topology.ts:55-65`) gains an optional `fileDigest` and makes
  `repositoryUrl` and `revision` optional, with the invariant that one of the two proofs is complete.
  `ObservedSource.provenance` records which one matched, which is ADR 0004's rule that recognition widens
  by provenance and never by lowering a band.
- The shim hashes each distinct repository file it names, once, memoised, bounded, **after**
  `original(input, init)` returns and before `span.end`, the slot `recordUsage` already uses
  (`outbound-fetch.ts:305`), so it adds nothing to the latency of the request being measured. Over the cap,
  Option B's behaviour rather than a lie.
- Nothing has measured this. It gets its own number before the default is turned on.

One name already exists for the marker that says which proof a span carried:
`ORCHESCOPE.sourceCapture = 'orchescope.source.capture'`, declared at
`packages/traces/src/attributes.ts:95`, with no reader, no schema field and no producer anywhere in the
tree. The producer writes it and the consumer reads it, turning a dead constant into the field that names
the proof.

**Recommendation: Option C.** It is the only one that makes `code_location` fire on a working tree, it uses
a mechanism this repository already built for exactly this purpose, and ADR 0007's own reversal condition
names it: reopen "if a real instrumentor can identify the executed declaration without a repository
coordinate" (`adr/0007:200-204`). Argued **in a record**, as an amendment. **Option B is the fallback** and
is strictly better than today. Option A alone ships a feature for the corpus.

### D7. The line

`packages/graph/src/source-match.ts:110-135` filters to declarations whose range contains the observed
line. The captured frame is the **call site**; a declaration's range is the **definition**. Omitting the
line is safe, because an undefined line skips the filter.

**Decision: emit it.** A line is real evidence, and suppressing it to raise a match rate is the shape of
confident wrongness this repository exists to remove. The D6 fallback refinement is what makes it safe:
`line_outside_declaration` now falls back to the rule the span would have used anyway, with the refusal
recorded as coverage.

### D8. The populations it does not reach, stated in the header

1. **A built application.** `getFileName()` returns the build output in all seven source-map
   configurations and all six deployment shapes measured, and zero of the eleven built corpus packages
   holding a model call ship a runtime source map; six of the eleven are Next.js.
2. **A framework that streams.** Three of eight Node cases, `ai`'s `streamText` in both spellings and
   `@openai/agents` with `stream: true`, reach the patched `fetch` from the framework's own stream
   scheduler with **no repository frame at any bound**. The same frameworks non-streamed put it at index 16
   and 13.

A third limit belongs beside them and is not a population of repositories: **this is a Node feature.**
Python has no `fetch`, and `openai` 3.3.1 sends through `httpx2` 2.12.0 rather than `httpx`. Measured cost:
**8 of 56 corpus entries are polyglot** (nested-aware: 17 JavaScript only, 30 Python only, 8 both, 1
neither), so their Python halves stay unattributed.

### D9. Records that have to change

- **ADR 0007** is amended by a new record: its identity becomes one of two accepted proofs, the second
  stated with its provenance, and "It emits nothing when the checkout is dirty" becomes "it emits nothing
  it cannot prove".
- **ADR 0014**'s sentence at `:144-148` is already conceded wrong in its own header. The new record says
  what replaces it and that the frame **does not** enter `OBSERVABLE_KINDS`: a call site names where a call
  was made, not a declared component that can be reported exercised, which `:238-239` warns against.
- **ADR 0015** decision 4's "the join keys on a location rather than on a name" is false of the matcher.

### D10. Falsifiers

- **F1, the join on a dirty tree.** Copy a corpus entry with a Node model call to a temporary root, dirty
  one tracked file, scan, trace, and require a `code_location` join whose provenance names
  `orchescope.code.file.digest`. Old tree: `revision_mismatch`.
- **F2, the fallback.** A component whose identity is refused `source_not_declared` must still join by
  `kind_and_name`. Old tree: unmatched. Its pair, that `revision_mismatch` does **not** fall back
  (`graph.test.ts:1299`), is a **guard**.
- **F3, the tracked-file rule.** A frame in an untracked file under the repository root must not be
  selected when a tracked frame exists deeper in the stack. Built on an installed tree, because no corpus
  entry has `node_modules` under its root.
- **F4, federation survives.** The `openai-agents-js-filesystem-mcp` expectation keeps its cross-repository
  `code_location` joins. A **guard** against D1 being narrowed back to containment.

The bundle-size assertion and "the shim patches nothing it did not patch before" are **guards**.

## Item 2: the goal's validation plan

The handoff asks whether the flag is the whole fix. It is not, and the gap is not close. Eight defects,
each verified by running the product's own functions.

| # | defect | evidence |
| --- | --- | --- |
| 1 | **The plan tells the operator to compare a run with itself, and banks two criteria as satisfied.** When the goal names no scenario, no `test` command is printed and `audit` records no run, so `latest` resolves to `baselineRunIds[0]`. | `create.ts:157-168` emits `test` per scenario id; `goal.ts:44-61` returns `[]` when the store holds no scenario; no `saveRun` in `audit.ts`; `goal.ts:90-93` takes the newest completed runs. Observed: `verdict = unchanged`, `AC-02 decided=true satisfied=true`, `AC-03 decided=true satisfied=true`. |
| 2 | **`metric_improvement` names metrics the comparison never computes.** | `create.ts:46-52` names `durationMs.p95`, `inputTokens`, `durationMs.p50`. `DEFAULT_COMPARED_METRICS` (`comparison/compare.ts:209-219`) holds none of them, and `durationMs` is a scalar in `RunMetrics` (`run.ts:58-83`) with no `p50` or `p95` key. Undecidable for all three of its only producible rules, flag or no flag. |
| 3 | **The printed compare can never reach the sample floor.** `minimumSamplesPerSide = 3` (`comparison/compare.ts:121`), and both the `latest` branch and the `run_` branch of `resolveSide` return exactly one run (`usecases/compare.ts:34-72`). `successRate` is not an incident metric, so a real regression is reported `indeterminate` and therefore undecided. | observed: `successRate moved from 1 to 0 and was judged indeterminate (needs at least 3 samples per side, has 1 and 1)` |
| 4 | **`--goal` is missing**, so the comparison is written with `goal_id` NULL and `latestComparisonForGoal`'s `WHERE goal_id = ?` never matches. | `create.ts:170-175`; `experiments.ts:69-86,115-123` |
| 5 | **The plan never prints `orchescope goal validate`.** The operator follows it verbatim and never runs the command that reads the evidence they just produced. | `create.ts:150-186` emits three argv shapes; the verb exists at `main.ts:325-333` |
| 6 | **The order is inverted.** `audit` is command[0] and is the only printed command that renders a goal judgement (`audit.ts:259-281`), but it runs before the comparison exists. | `create.ts:152-156` versus `:170-175` |
| 7 | **`manual_review` is decided by nothing**, and `validated` is `every(satisfied)`, so a goal cut from a finding requiring review can never validate. | `validate-plan.ts:204-205,240`; no recorder anywhere for `reviewedBy`, `reviewer` or `human_review` |
| 8 | **`compare --goal` does not check the goal exists.** A mistyped id stores a comparison attached to nothing and reproduces the exact symptom the flag was added to remove. | no `goalById` on the path: `run-commands.ts:453-464`, `usecases/compare.ts:24,160`, `comparison/compare.ts:283,375` |

Two rows of the plan are sound, confirmed rather than assumed. `scenario_passes` is printed with everything
it needs (`create.ts:157-168` against `main.ts:242-250`; the store query needs no goal association,
`scenarios.ts:45-69`). `orchescope audit --json` parses, and `--json` is cosmetic because
`finding_resolved` is judged from the stored scan.

### The decision

> **The flag is not the whole fix. The principle in the comment at `create.ts:85-96` is the fix, applied to
> the whole plan: state no criterion whose deciding command the plan will not name, and name no command
> that cannot decide it.**

Staged, with the scope decision made explicit because the last stage reaches into the comparison engine.

**2a. Stop the false pass. Gate the metric criteria and the compare command on the plan being able to
produce a candidate**, that is on `validationScenarioIds.length > 0` as well as `baselineRunIds.length > 0`.
Today both are gated on the baseline alone (`create.ts:317-323`), which is the wrong question: a baseline
without a candidate is a self-comparison. This is the only defect that produces a *wrong* answer rather
than no answer, so it goes first.

**2b. `--goal <goalId>` on the emitted compare**, and reject an unknown goal id at the use case. The id is
available: `makeGoalId(sequence)` is computed at `create.ts:301` from the same input.

**2c. Print `orchescope goal validate <goalId>` last**, so the plan ends at the command that renders the
decision, and the inverted order stops mattering.

**2d. Do not emit a criterion the printed commands cannot decide.** As things stand that removes
`metric_improvement` entirely (defect 2) and `metric_not_worse` on `successRate` (defect 3), leaving
`duplicateSideEffects`, which is an incident metric and is decided whenever one side is zero. This is the
comment's own remedy and it is uncomfortable, because it strips a goal document of its performance terms.

**2e. Or fix the engine so those criteria can be kept.** Two changes, both real. `DEFAULT_COMPARED_METRICS`
gains quantile metrics computed with `quantile` from `@orchescope/domain`, which reconciliation already
uses. And `resolveSide`'s `latest` means the repetition set of the newest scenario result rather than one
repetition, which is what repetitions exist for and what the `runIds` array and the `baselineRuns` array
already accommodate.

**2f (droppable). A deciding act for `manual_review`**, and the plan names it. Carries a `Goal` schema
change. Omitting the criterion instead would silently drop a safety requirement that
`scope.requiredApprovals` also records; excluding it from `validated` would claim validation without the
review.

**Recommendation: 2a, 2b, 2c and 2e, with 2d as the fallback if 2e is out of scope, and 2f separately.**
2d without 2e is honest but leaves the loop unable to say anything quantitative, which is most of what a
goal is for.

### One more defect of the same class, in a more visible surface

`packages/report/src/commands.ts:33-40` prints `orchescope test --scenario <id> --repeat <n>`, and the CLI

being handed a list.**

## Item 3: a scenario an operator who did not build this repository can write

### What the audit actually says

Measured by running the real CLI against copies of the pinned checkouts:

| repository | findings | goal-eligible | blocked by a scenario? |
| --- | --- | --- | --- |
| `openai-cs-agents-demo` | 3 | 0 | **yes**, `prompt-injection-boundary` |
| `email-agent` | 1 | 0 | no, `observability-coverage`: "a next step for the operator rather than a code change" |
| `local-deep-researcher` | 3 | **1** | no, `model-call-without-timeout` is already eligible |

**The handoff overstates this by two repositories.** Only `openai-cs-agents-demo` is blocked by the absence
of a scenario.

### What the predicate requires, established stepwise

`prompt-injection-boundary` (`static-policy.ts:1013-1022,1069`) was probed against its own e2e fixture with
the state directory cleared between each step:

    no scenarios directory                                   eligible = false
    the init --scenario template, moved verbatim             eligible = false
    a minimal four-field scenario                            eligible = false
    plus fault kind prompt_injection_in_content, target '*'  eligible = false
    plus evaluator kind no_duplicate_effects                 eligible = false
    plus expect.prohibitedEffects with one entry             eligible = TRUE

All three clauses are required simultaneously. `fault.target` must be `*` or an exact member of
`{source.id, source.identity.localName, source.displayName}` (`static-policy.ts:1006-1012`):
`lookup_order` and `tool:lookup_order` both work, `not_a_real_component` does not, and the two accepted
spellings are recoverable only from a prior audit's JSON. The template's faults block is `faults: []` and
names none of this vocabulary.

**And the scenario need not be runnable.** With `target.command` set to
`['definitely-not-a-real-binary-xyz','--nope']` and the three clauses intact, the finding reports
`eligible = true` and the product prints `orchescope chaos --scenario example` back as the suggested
experiment; running it prints `error Running "definitely-not-a-real-binary-xyz" is not permitted by the
current policy.` **A four-line unrunnable YAML moves the same number a real scenario would.** Any claim
that shipping a scenario file makes the third verb true has to reckon with that.

### The operator path exists, and breaks in four measured places

Run against a copy of `corpus/.cache/vercel-ai-chatbot`:

- **It starts well.** `orchescope --cwd <copy> init --scenario` writes a valid template and offers the
  repository's own commands as comments: `npm run start (package.json:8)`, `npm run dev (package.json:6)`.
  Moving it to `scenarios/` and running `orchescope test --scenario example` loads, parses, passes the
  permission gates and executes.
- **Editing the scenario silently does nothing.** `packages/usecases/src/scenario.ts:32-34` returns the
  **stored** scenario before the disk file is consulted, and the disk branch fires only for a reference
  ending `.yaml`. After editing `repetitions` from 3 to 1, `orchescope test --scenario example` still ran 3
  repetitions, with no message. Only an unrelated `orchescope audit`, which calls `discoverScenarios`,
  re-synced it. **Iterating on a scenario is the whole activity `init --scenario` starts, and it is
  inert.**
- **The template offers commands its own evaluator cannot pass.** Both candidates are long-running servers
  (`next start`, `next dev --turbo`) and the only evaluator the template emits is `exit_code: equals 0`. A
  process that never exits cannot satisfy it, and one that exits 0 has stopped being the system.
- **A failure says nothing.** The human output for a failed run is
  `x exit_code: passed in 0 of 3 repetitions that ran this evaluator`, with no exit code and no reason.
  Both exist and are reachable only with `--json`: `exitCode 127`, `failureReason 'the target exited with
  code 127: ...'`.

### The design

> **A rule that gates eligibility on a scenario declares the scenario it needs, structurally, where it
> declares its remediations. The finding carries that requirement when it is unmet. `orchescope init
> --scenario` composes it, with the one field only the operator knows left blank and the repository's own
> candidates beside it. And the path an operator actually walks is made to work.**

1. **The predicate becomes data.** Each rule computes it inline as a `context.scenarios.find`. The same
   shape, declared, is a small record: required fault kinds and the target the rule resolved, required
   evaluator kinds, and whether prohibited effects are needed. One definition, used both to search and to
   say what is missing.
2. **The finding carries the requirement when it is unmet.** Today an unmet predicate yields prose and
   drops `suggestedExperiment` entirely, which is backwards.
3. **`init --scenario` composes rather than templates**, and **candidate discovery becomes nested-aware**.
   Measured: `startCommandCandidates` reads only root manifests
   (`packages/workspace/src/start-command-candidates.ts:64-121`) and returns **zero candidates for 32 of
   the 56 corpus entries**, including all three the handoff names. `openai-cs-agents-demo` has its Next.js
   application at `ui/package.json` and its Python service at `python/`.
4. **A scenario read from disk wins over the stored copy**, so editing one takes effect. This is the defect
   that makes the operator path inert and it is the cheapest of the four.
5. **A failed repetition prints its exit code and reason** in the human document, not only in `--json`.
6. **The composed template does not offer a command its own evaluator cannot pass.** A long-running server
   needs a different evaluator, or the candidate is offered with the reason it will not satisfy
   `exit_code`.

### The fourth defect, and why item 3 is a lie without it

`packages/scenarios/src/run.ts:208-212`:

    repetition.evaluators.every((result) => result.skipped === true || result.passed)

**A skipped evaluator counts toward passing.** `metricThreshold` skips when a metric was not measured
(`packages/scenarios/src/evaluate.ts:231-238`), which is the right refusal and the wrong consumption. A
foreign target that emits no spans and writes no result file produces evaluators that all skip, and the
`ScenarioResult` reports `passed`. `scenario_passes` is then satisfied on no evidence.

This is item 2's defect 7 in the opposite direction. One principle covers both: **a term nobody evaluated
is neither satisfied nor failed.** The fix mirrors `validate-plan.ts`: a result passes when at least one
evaluator was decided and none was left undecided, and the undecided ones are named. **Risk: this can move
corpus numbers and can flip the demo scenarios.** Gated on a measurement of what skips today across
`apps/demo` and every exercised corpus entry, and a **separate commit**.

Two further traps a foreign operator hits, recorded so the composed template can warn rather than fixed
here. `output_contains_all` does not read stdout; it reads `targetResult.output` or the root span's
`orchescope.task.output` (`packages/scenarios/src/repetition.ts:70-73`). And a fault needs the target to
implement the cooperative protocol (`packages/runtime/src/session.ts:174-176`): **no shipped runner applies
a fault to an uncooperative target**, and `startFaultProxy` has no non-test caller. `Scenario.cleanup`
(`packages/schema/src/scenario.ts:144-149`) is executed by nothing.

### Where the demonstration lives, and how far it can go

A scenario is read from `<root>/scenarios` and the loader refuses anything outside the root
(`packages/scenarios/src/load.ts:143-156`). Writing one into a pinned checkout would break a digest pin or
move coverage counts, and committing a hand-written YAML for a third-party repository would be the fixture
problem with a different author. So the demonstration is an end-to-end test over a copy.

- **F9, eligibility, provable offline.** On a copy of `openai-cs-agents-demo`: scan and assert no finding
  is goal-eligible; run the composed `init --scenario`; fill in only `target.command` from the offered
  candidates; rescan; require `prompt-injection-boundary` to become goal-eligible and a goal to be
  cuttable. Fails twice on the old tree: the static template satisfies no predicate, and candidate
  discovery offers that repository nothing.
- **F10, the operator path.** Edit a scenario on disk and require `orchescope test` to run the edited one.
  Fails on the old tree.

**What cannot be promised.** Running that scenario needs a provider key:
`openai-cs-agents-demo-exercised` declares `requiresEnvironment: [OPENAI_API_KEY]`. Five of the nine corpus
exercise entries run keyless, but each reaches for the target framework's own extension point from a
bespoke driver Orchescope wrote (`setDefaultModelProvider`, `TestModel`, a `BaseLLM` subclass, the
checkout's own `models.mock.ts`). **This repository ships no stub provider.** `apps/demo/src/model.ts` is
inside a package with `private: true` and `exports: null`. `fault-proxy.ts` needs a real upstream and only
serves failures. So a runnable non-demo scenario needs either a key or a new loopback server speaking the
provider wire protocols, which is separate work and is named here rather than assumed.

## What the tracing corrected

1. **"Is this path under the audit root" is not the rule.** It loses the corpus's only `code_location`
   joins, which span two repositories, and it emits the wrong path shape for a `subpath` entry. This
   contradicts the handoff at `0.9.4-remaining-work-handoff.md:82-86`.
2. **`code_location` is not a name-free rule.** `source-match.ts:57-64,97` keys on
   `file|kind|normalisedName`. A framework nobody wrote a reader for declares nothing, so the match is
   refused `source_not_declared`. The scope's "The catalogue is not consulted" and ADR 0015's "the join
   keys on a location rather than on a name" are both false of the matcher. What attribution buys is
   disambiguation among same-named declarations, and a file and line on runtime-only components.
3. **The prototype's gates are not corpus-specific**; three of four mirror consumer gates. The corpus is
   what is unrepresentative, because `checkout --force --detach` manufactures every condition they test.
4. **The handoff overstates item 3 by two repositories.** Only `openai-cs-agents-demo` is scenario-blocked.
5. **`metric_improvement` has never been decidable**, for any rule, in any run.
6. **`pnpm corpus --record` does not work.**
7. **The corpus contains no built output at all**: no `.next`, no `out`. Measurement 3's finding was
   established on purpose-built configurations. Separately, "11 built packages holding a model call, 6 of
   them Next.js" does not reproduce read-only: deduplicating by origin gives 10 distinct Next.js packages
   with a build script, 9 declaring a model or agent SDK. The figure is quoted from its own document, not
   re-derived; what is recorded is that the population is ambiguous.
8. **Capture cost is flat once the stack is deeper than the bound**, not flat in depth. At depth 5 the
   limit-20 cell is 5,797 nanoseconds, 37 per cent below the 9,225 at depth 20.
9. **The per-capture allocation is 24.7 bytes at the recommended bound, not 28**, and it is an
   `Error.captureStackTrace` figure; no memory figure exists for `getCallSites`.
10. **`docs/guides/runtime-tracing.md:151`** documents `vcs.repository.ref.revision`, which nothing reads.
    The consumer reads `vcs.ref.head.revision`.

## What this design does not fix

- **The Python half.** No producer, and no transport to patch that is not a catalogue. 8 of 56 entries are
  polyglot.
- **Built applications and streaming frameworks.** Stated, not solved.
- **A repository that is never run.** The declared half stays a catalogue, and ADR 0015 stays true.
- **The framework nobody wrote a reader for.** It gets a located runtime-only component and not a join.
- **A repository that commits its build output**, whose frames name tracked files the traversal skipped.
- **A runnable non-demo scenario without a provider key.** No stub provider exists and building one is
  separate work.
- **A fault on an uncooperative target.** `startFaultProxy` has no non-test caller.
- **`Scenario.cleanup`**, declared and executed by nothing.
- **`finding_resolved` against a pre-goal scan.** `rescanned` is true whenever any scan is stored
  (`goal.ts:206`), with none of the `startedAt >= goalCreatedAt` guard `scenario_passes` carries
  (`validate-plan.ts:140`). Lower confidence than the eight above, and recorded rather than fixed.
- **The dead-name gate's blind spot**: 20 scoped package names are invisible to it, and it cannot fail a
  build.
- **`scripts/package.mjs:132-133`** does not list `dist/instrument.mjs` among its required files, so a
  build that dropped the shim would still pack and pass the smoke test.
