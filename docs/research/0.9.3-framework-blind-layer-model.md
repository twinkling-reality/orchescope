# The framework-blind layer model, and the backstop that makes silence impossible

A design, for review, before any code. It states the layer model Orchescope is to hold from now on, where
each existing adapter sits inside it, what a backstop has to guarantee for the model to be true, and what
the three defects recorded by the [0.9.2 acceptance check](0.9.2-acceptance-used-holdouts.md) cost to fix.

Every number below was measured against this repository at `d2c3720`, using the repository's own analyzer,
against the populated corpus cache and against the eight acceptance targets acquired at their pinned
revisions. The command that produced each figure is beside it. Nothing here is derived from the report
alone; the report was reproduced first.

## The invariant

    1. Protocol, framework-blind. MCP, the OpenTelemetry generative AI conventions, OpenAI-compatible
       HTTP path shapes.
    2. Structural, framework-blind. Imported-construction shapes, effects.
    3. Bounded refusal. Anything layers 1 and 2 see and cannot name is said out loud, with a source
       location.
    4. Framework adapters. Depth only. Never required for correctness.

Layers 1 to 3 are sufficient for correctness. Layer 4 adds resolution. A distribution nobody has written a
reader for degrades to "there is a construction here this build did not read", never to silence and never
to a wrong claim.

## Why layer 3 may widen where layer 4 may not

[ADR 0004](../architecture/adr/0004-provenance-not-confidence.md) refuses a widening whose only safety
mechanism is a lower confidence band, and its measurement is that an import recognizer fires 40 times on
`open-agent-platform`, a pinned `not_agent_system` entry with a ceiling of 26 components. That record is
the reason this repository has thirteen hand-written readers rather than one convention reader.

It does not bind layer 3, and the distinction is not a loophole. ADR 0004 is about **recognition**: a
producer that emits a `Component`, which enters `AGENT_SYSTEM_KINDS`, flips `agentSystemDetected` at
`discover.ts:919`, and cascades into every population a rule
measures. A bounded refusal emits an `UnsupportedArea`
(`graph.ts:138`). It is not a component, it has no identity, it
enters no population, it moves no metric, and it cannot flip detection.

The existing net already says exactly this in its own header
(`unclaimed-imported-construction.ts:13`):

> That sentence is a claim about the repository. What happened is a claim about this build.

So the two layers are held to two different standards, and they are the right two:

| | layer 4 recognition | layer 3 refusal |
| --- | --- | --- |
| emits | `Component`, `Relation` | `UnsupportedArea` |
| failure mode | a wrong claim about the repository | noise |
| precision mechanism | provenance, per ADR 0004 | provenance for tier, then bounding and sampling |
| may widen on structure alone | no | yes, if bounded |

**The conjunction at
`unclaimed-imported-construction.ts:52`
is layer 4's standard applied to a layer 3 artefact.** That is the root cause of most of the fifteen silent
misses, and correcting the category is the design.

## The backstop

### What the analyzer already records

Verified by running `analyzeFileSet` over fixtures reproducing the exact missed shapes. No analyzer change
is needed for any of it.

| shape | fact that carries it | example, verified |
| --- | --- | --- |
| Python keyword-only call | `CallFact.args = [{kind:'object', role:'keywords', entries}]` | ADK's tenth agent, `name`/`model`/`instruction` all present |
| Python positional + keyword | same, keyword half complete | AutoGen's `AssistantAgent("assistant", client, system_message=…)` |
| class definition and base class, **Python only** | `DefinitionFact{kind:'class', initializer:['Workflow']}` | `class AgentWorkflow(Workflow)`; the base resolves through `ModuleFacts.imports` |
| class definition and base class, **JavaScript and TypeScript** | **nothing.** `class MyFlow extends Workflow` produces a `DefinitionFact` with keys `async, decorators, exported, kind, location, name` and no `initializer` | verified by running the analyzer; see the limit below |
| decorator | `DecoratorFact.origin` complete | `@step` carries `module: 'llama_index.core.workflow'` |
| member call on a bound receiver | `AssignmentFact{target:['this','ollama'], value:{kind:'call', path:['Ollama']}}` | bridges the origin-less `this.ollama.chat({model})` |

The net today consults exactly one of these. It iterates `module.calls`
(`unclaimed-imported-construction.ts:146`)
and never reads `definitions`, `decorators` or `assignments`. That is why a class definition "cannot be
seen at all": not because the fact is missing, but because the net does not look.

### Four nets over four fact families

- **N1, construction.** `CallFact` whose `origin` names a foreign distribution.
- **N2, subclass.** `DefinitionFact{kind:'class'}` whose `initializer` resolves through the module's import
  table to a foreign distribution. **Python only until the JavaScript analyzer records `extends`.** That is
  an analyzer change in `packages/source-analysis/src/javascript/`, and it is the one piece of this design
  that is not free.
- **N3, decorator.** `DecoratorFact` whose `origin` names a foreign distribution.
- **N4, bound receiver.** A call with no `origin` whose `calleePath` prefix matches an `AssignmentFact`
  target whose value was a foreign construction.

- **N5, annotation.** A parameter annotation, return annotation or return value naming a symbol that
  resolves to a foreign distribution. Added after the completeness review; not in the measurement below.

Plus a **re-export bridge**: a local specifier is followed to the module it names, and that module's own
imports are asked where the symbol came from. Without it, `from .llm import Agent` is refused as local
before any test runs, which is the most common production shape there is.

Together these cover every shape the brief names: keyword-only constructions, class definitions and
subclassing, decorators, factory functions, and non-call declaration sites. **The measured numbers below
cover N1 to N4 only**, so they understate recall and are the floor rather than the result.

### The provenance gate: what "foreign" means

This is where precision comes from, and it is provenance in exactly ADR 0004's sense: whose file is this.
A specifier is foreign when it is none of the following.

1. Relative, absolute, or `node:` prefixed. Already handled.
2. **A Node builtin or a Python standard-library module.** Taken from `module.builtinModules` and from the
   interpreter's own `sys.stdlib_module_names`, not from a list this repository maintains.
3. **A path alias the repository declares**, read from `compilerOptions.paths` in `tsconfig.json` or
   `jsconfig.json`. This must be parsed JSONC-tolerantly: `"@/*"` contains the characters `/*`, and a naive
   block-comment strip destroys the file. My prototype hit exactly that bug.
4. **A module path this repository defines.** `localModules`
   (`local-modules.ts:56`) is Python-only and registers
   top-level roots only, so `marketing_posts.llm`, `langgraph_api.cache` and `computer_use_demo.loop` are
   read as distributions today.
5. Claimed by an adapter. Already handled by `moduleMatches`.

Measured effect of gate items 2 to 4, over the whole corpus cache:

```
CONJ=2  DISJ=96  after the provenance gate: 11
```

The gate removes `typing`×10, `asyncio`×3, `dataclasses`×5, `json`, the two `@/hooks/…` hits on the ADR 0004
canary, and every first-party deep module, while keeping both existing pins (`litellm`, `smolagents`).

**Declaredness in a dependency manifest must rank, not gate.** `readManifests` is root-only, so gating on it
drops `@langchain/openai`×11 in `langgraphjs`, `autogen`×8 in `gpt-researcher` and `claude_code_sdk` in
`anthropic-quickstarts`, all real, all invisible to a root manifest in a monorepo or an optional extra. A
gate there manufactures exactly the silence this design exists to remove.

### Generalising the predicate, not the list

The brief asks that defect A be fixed by generalising rather than by adding names. Three candidates were
measured.

**Candidate 1, disjunction.** Replace `tools AND model` with `tools OR model`. Precise, and it catches the
ADK tenth agent. It does not catch T1's `AssistantAgent`, whose key is `model_client`, and it catches
nothing in T6.

**Candidate 2, vocabulary-free structure.** A callable-valued argument, a prompt-shaped literal, a subclass
that declares behaviour, a decorator on a function. This is the shape that needs no names at all, and the
measurement destroys it:

| repository | sites under vocabulary-free structure | dominated by |
| --- | --- | --- |
| `ai-chatbot` | 280 across 20 distributions | `react` ×231 |
| `open-agent-platform` | 102 | `react` ×87 |
| `flask` | 36 | `click` ×20, `werkzeug` ×10 |
| `axios` | 4 | `gulp` |

Every React hook takes a callback; every Click command is a decorated function. There is no threshold that
separates these from `defineChatSessionFunction({handler})`.

**Candidate 3, segment-stem matching. Recommended.** Split a key into its camelCase and snake_case segments
and match a segment against a stem, rather than matching the whole key against a name:

    MODEL_STEMS   model, llm
    TOOL_STEMS    tool, function
    PROMPT_STEMS  prompt, instruction, systemmessage

Seven stems replace nine exact names, and they match `modelPath`, `model_client`, `chatModel`,
`languageModel`, `systemPrompt`, `toolChoice`, `managed_agents` without any of them being written down.
This is a generalisation of the predicate. It is what the brief asked for and the measurement supports it.

### The declaration-builder suppressor

`toolsArgumentLooksLikeJsonSchemas` keeps an OpenAI tool-schema payload quiet. It has a naming-independent
sibling that is needed once the predicate widens: **an object argument of two or more entries where every
value is a call rooted at the same name the construction itself is rooted at.**

Verified shape, from the analyzer:

```
z.object({ model: z.string().optional(), tools: z.array(z.string()) })
  calleePath   ['z','object']
  entries      model -> {kind:'call', path:['z','string','optional']}
               tools -> {kind:'call', path:['z','array']}
```

A schema is being described, not an agent built, and no name appears in the test. Measured: it takes
`mcp-filesystem-server` from 1 tier A site to 0 and keeps `agentgauge` at 0, **with no recall lost on any of
the eight targets**.

Reproduce with the probe under
`docs/research/` companion scripts, or directly:

```
node -e "import('./packages/traces/src/model-endpoints.ts').then(m=>console.log(m.isInferencePath('/users/1/messages')))"
```

### Bounding, so widening cannot become noise

Per distribution, not per site. One refusal names a distribution, the count of sites, and up to a fixed
number of located examples. `SAMPLE_CEILING` already exists at
`unclaimed-imported-construction.ts:28`
and `discover.ts` already samples topology refusals across two populations, so the shape is established.
Tier B collapses to a single line naming the distributions and nothing else.

**Sample per distribution, not globally.** The current sort is alphabetical by `file:line` and the cap is a
flat 10, so one noisy directory can evict a pinned construction, and the overflow row carries no location
while corpus acceptance requires a located area. Widening the predicate makes this reachable: the widened
predicate yields 15 areas on `langgraphjs` alone.

**`area` and `reason` are pulled in opposite directions, and the split has to be exact.** The corpus
observation records only `area` (`scripts/corpus/observation.mjs`), so a *count* in that string makes the
largest entries churn on every unrelated edit. But the terminal renders only `area` as well, and says so as
policy: `unsupportedRows` at `apps/cli/src/terminal/gap-rows.ts:115-124` emits `text: area.area` and its
header reads "The area and its classification, and never the paragraph behind either." Advice to "put the
new detail in `reason`" therefore makes the refusal **invisible to the human document**, which is the one
surface the invariant exists to protect. The split:

- `area` carries the identifying content and nothing variable: the distribution, the symbol, and the
  `file:line`. This is what the current string already does and it must stay that shape.
- `reason` carries the paragraph, the key that fired, and every count.

### The display ceiling is a third serial bound, and it can still silence a located refusal

`ROW_CEILING = 4` at `apps/cli/src/terminal/gap-rows.ts:31` bounds the **entire** gap region, and
`unsupportedRows` is **fourth** in priority, after failed adapters, the truncation row and skipped-file
rows. Overflow collapses to `N more kinds of gap, in the report`. A repository with a failed adapter, a
truncated scan and a skipped file has consumed every slot before a located unclaimed construction is
considered.

So there are three ceilings in series between a construction and a reader: `SAMPLE_CEILING = 10` in
discovery, the per-distribution sample above, and `ROW_CEILING = 4` in the terminal. **The invariant is a
claim about what the reader is told, not about what the graph contains.** Decided in ADR 0014: keep the
four-row bound and the deliberate priority order, and make the overflow row name the kinds it dropped
rather than only how many. That is the minimal change that closes the fourth ceiling without reordering a
priority the terminal argues for in its own header.

**Tier B carries no argument predicate at all, and that is what makes silence structurally impossible.**

This is the correction that the completeness review forced, and it is the most important paragraph in this
document. Every widening considered above keys on argument *shape*, and argument shape is a property a
construction may simply not have. `objectEntries`
(`unclaimed-imported-construction.ts:44-50`) returns `[]` for any argument that is not an object or a
keyword bundle, so

```
agent = create_agent(config)      # one identifier argument
agent = build_agent()             # no arguments at all
```

from an unclaimed distribution die under the current conjunction **and under every widening proposed here**,
including segment-stem matching. A wider argument predicate makes silence less likely on measured shapes and
leaves it possible on unmeasured ones. That is not the invariant.

So tier B is defined by provenance alone: **every foreign distribution this repository constructs from,
subclasses, decorates with, or annotates against, that no adapter claims**, aggregated into one bounded
line naming the distributions and the site counts. No key test, no stem, no shape. Tier A ranks and
locates; tier B guarantees. There is then no path through the net that returns nothing while such a
construction exists, and the guarantee does not depend on any vocabulary.

## Fix A

Change [unclaimed-imported-construction.ts](../../packages/discovery/src/unclaimed-imported-construction.ts):

1. Replace `hasToolsAndModelKeys` (`:52`) with a disjunction over segment-stem matching.
2. Move the foreign-distribution test into its own module, since the four nets share it and this file is
   already at its concept boundary.
3. Add N2, N3 and N4 as separate passes over `definitions`, `decorators` and `assignments`.
4. Aggregate per distribution; keep `toolsArgumentLooksLikeJsonSchemas` (`:67`) as-is, it is the guard that
   keeps an OpenAI tool-schema payload quiet.

Path-alias and stdlib provenance are prerequisites, not extras. Landing the disjunction without them puts
`@/hooks/use-fetch-preselected-tools` on the ADR 0004 canary.

## Fix B

The brief asks for path-shape recognition independent of host. Two corrections, both measured.

**B is two defects, not one.**

```
isInferencePath('/v1/chat/completions')  true    <- host gate is the only blocker. T6, vLLM, LM Studio, OpenRouter, Together.
isInferencePath('/api/chat')             false   <- Ollama's native API. The host gate is not the only blocker. T5.
isInferencePath('/api/show')             false   <- correct; a metadata endpoint is not inference.
```

Removing the host gate fixes T6 and every OpenAI-compatible self-host. It does **not** recover T5's model
half. Teaching `INFERENCE_OPERATIONS` `chat` and `generate` is a separate decision with its own
false-positive surface, and it belongs to layer 1's protocol vocabulary rather than to any framework.

**`isInferencePath` cannot be reused host-independently as written.** Measured:

```
/users/1/messages        true
/workflows/x/invoke      true
/v2/predict              true
/graphql/responses       true
```

Its own header says it is a question about a provider host. The unrecognised-host branch needs a tighter,
version-anchored predicate covering only the OpenAI-compatible shape, while the loose table stays for a
recognised host where it is already measured.

**A pre-existing asymmetry to fix first, in its own commit.** `hostOf`
(`request-address.ts:38`) returns the full authority;
the shim uses `url.hostname`. Verified:

```
modelEndpointForHost('api.openai.com')            -> openai
modelEndpointForHost('api.openai.com:443')        -> undefined
modelEndpointForHost('user:pass@api.openai.com')  -> undefined
```

A source that writes an explicit port is unrecognised statically and recognised at runtime, today. That is a
manufactured delta between the two halves of the join, and it also puts userinfo credentials into
`details.host`.

**Provider identity.** Recognised host yields a named provider. Unrecognised host yields
`model:unspecified/<model>`, using the word `unspecified` that `effects.ts`, `vercel-ai-sdk.ts` and
`model-sdk.ts` already write for an unsettled half. Never a host-derived provider segment: a host-derived
segment can never equal a declared segment, and it merges every model on one port. Where the model name is
also unreadable, refuse rather than mint a component literally named `unspecified`.

**Both halves in one commit.** Fixing the shim without `effects.ts:597` produces a runtime `model` whose
static counterpart is an `external_service`; the reconciler keys on kind, so no join is possible and
`exercised-not-declared` fires at high severity. T6's low-severity false claim would become a
high-severity one.

**A same-origin request must never mint a model.** `isSameOrigin`
(`request-address.ts:36`) must be checked before the
path test. A Next.js app posting to `/api/chat/completions` is not calling a provider. The host gate made
this question unreachable; removing it makes it live.

## Fix C

The anchor stays. It is the `from` of `invokes_model`, it carries declared timeouts, it is the prompt
consumer, and provider qualification and nested-binding identity hang off it. What is wrong is that it is
called an `agent` and counted toward detection.

Four mint sites, all computing `sourceIdentity('agent', file, enclosing)`:
`vercel-ai-sdk.ts:248`,
`model-sdk.ts:937`,
`:1022`,
`:1156`, plus the independent
`promptConsumerForModelCall` at `model-sdk.ts:1076`.

The population is exactly discriminable by metadata that already exists. Measured:

| repository | agents from these sites |
| --- | --- |
| `vercel-ai-chatbot` | 8 `single generation call` + 1 `tool using generation call` |
| `anthropic-quickstarts` | 4 `model call site` |
| `tubemind` | 2 `model call site` |
| `docent`, `gpt-researcher` | 0; their agents come from framework adapters and are untouched |

The `tool using generation call` branch has structural evidence of a loop and stays an `agent`.

### Two options, and this one needs your decision

**Option A, a new kind `model_caller`.** Pairs with the relation it anchors exactly as `provider` pairs with
`served_by_provider`. `model_caller:basiccompletion` is a true sentence where `agent:basiccompletion` is
not. Cost: a schema change, a document-version decision, and every kind-keyed set below.

**Option B, reuse `entrypoint` with a new tag.** `ensureScope`
(`effects.ts:412`) already mints this exact shape as
`kind:'entrypoint'` with `INFERRED_ENTRY_POINT_TAG` and already draws `invokes_model` from it. This buys
exclusion from `OBSERVABLE_KINDS`, exclusion from `AGENT_SYSTEM_KINDS`, candidacy in `entryPoints`, and
exclusion from `REACHABILITY_KINDS` for free, with no schema change.

**Option B was chosen**, on the duplication measurement above rather than on cost. The objection to it,
that the graph should not say "entry point" about a function that is not one, is answered by the tag: the
repository already made this decision for effect frames and `isInferredEntryPoint` exists to draw the
distinction. Two vocabularies for one concept is the failure `call-relation.ts` and
`inferred-entry-point.ts` each warn against in their own headers. Falling out of `HEADLINE_KINDS` is the
correction rather than a loss, because counting these as agents is the defect.

### Every kind-keyed site, whichever option is chosen

| set | file | effect |
| --- | --- | --- |
| `AGENT_SYSTEM_KINDS` | `audited-system.ts:11` | **exclude.** This is the fix. |
| `OBSERVABLE_KINDS` | `analysis.ts:381` | **exclude, and record the refusal in writing.** Including it recreates the 0.9.2 defect: no span can carry a source-only enclosing-function identity, so it would report `declared-not-exercised` forever. The honest cost is that it can also never be reported as exercised. |
| `entryPoints` | `analysis.ts:100` | **include.** Otherwise every tool the anchor reaches becomes an unreachable-component finding. |
| `REACHABILITY_KINDS` | `static-policy.ts:1069` | exclude. |
| `MODEL_DRIVEN_KINDS` | `static-policy.ts:622` | **include, or lose `side-effect-approval-boundary` coverage** for any hand-written loop reaching a consequential operation directly. This is a security-rule regression if missed. |
| `wideFanOutDrafts` | `static-policy.ts:1208` | hard-filters `kind === 'agent'`. **Decided:** widen it to include the frame, since a frame calling eight tools is exactly what the rule is for. |
| topology strength | `static-policy.ts:1291` | repositories whose only agents were frames stop receiving the strength. Correct under the invariant, visible as reduced positive output. |
| `repeatedContextRule` | `runtime.ts:377` | stops firing on reclassified frames. |
| `HEADLINE_KINDS` | `apps/cli/src/terminal/source-headline.ts` | needs the new noun under Option A. |

**Two hard constraints.**

`details.for` must equal `kind` or `componentViolations`
(`invariants.ts:22`) reports a violation. Shipping the new kind
with `details: { for: 'agent' }` is not a cosmetic lie, it breaks graph construction. A matching `details`
variant is mandatory.

`isRenameOf` requires an unchanged kind (`identity.ts:89`), so
`compare_runs` will read the reclassification as delete-plus-add on every affected repository. Either write
a `ComponentAlias` with reason `renamed`, or record the one-time discontinuity deliberately.

### Detection will not flip on T2 and T6 from this fix alone

`model` is also in `AGENT_SYSTEM_KINDS`, and both targets carry a model component. The claim being
corrected is "this repository contains N agents", which is the component inventory and the headline, not the
boolean. An acceptance criterion written as "`agentSystemDetected` flips to false" would report this fix as
not working. State it as the inventory claim.

Separately: `d2c3720` already removed `embed` from `GENERATION_CALLS`, and T2 at HEAD now reports
`agentSystemDetected: false` with **0** components, against 2 in the published 0.9.2. Three of the report's
four false positives are already fixed. Only T6's seven remain.

## The schema decision, under Option A

- `COMPONENT_KINDS` (`component.ts:36`) gains one entry, with a
  doc-comment paragraph in the existing voice naming its producer, since the file's own rule is that a kind
  without a producer is a defect. The producer exists on day one: four sites already mint it.
- `UnsupportedAreaKind` is a **closed enum published in three schema documents** (`system-graph.v1.json`,
  `report.v1.json`, `federation.v1.json`). The `Type.Optional` on the *field* is not openness of the
  *enum*, which I initially read it as. Reusing `unclaimed_imported_construction` for the new nets moves no
  document but redefines a published term whose current definition names the conjunction; minting a second
  kind changes three documents. **Decided in ADR 0014:** reuse `unclaimed_imported_construction` for a
  located site with its definition rewritten to be provenance-shaped, and add one kind for the tier B
  aggregate, because an unlocated claim about a distribution is a different claim from a located one about
  a site, and the corpus acceptance requires a located area.
- **A new `ComponentKind` is reader-visible and does move the version.** A stored graph written by this
  build is unreadable by an older one.
- `pnpm schemas` regenerates; `pnpm schemas:verify` compares 13 documents.
- **`tests/e2e/rule-input-producers.test.ts` will not catch a mistake here.** It filters `COMPONENT_KINDS`
  down to kinds a rule file literally names, so a new kind no rule mentions is asked nothing and the test
  passes green. Do not treat it as the gate.
- **`schemas/manifest.v1.json` and `v2.json` are not emitted by `scripts/emit-schemas.mjs` and not compared
  by `--check`.** They already omit `workflow` and `workflow_step` from their `ComponentKind` enum while the
  live readers accept both. A new kind widens a published untruth by one more member and CI reports success.
  This is a pre-existing defect; flagging it, not fixing it under this change unless you want it in scope.
- There is **no compile-time safety anywhere**: no `Record<ComponentKind, …>`, no switch on component kind,
  no exhaustiveness helper. Every kind population is a `Set<string>`. Two are already stale:
  `static-policy.ts:1073` keeps deleted `worker`, and `exports.ts:30` keeps deleted `project` and omits live
  `evaluator`. The table above is the checklist because the compiler is not.

## Falsifiers

Every fix carries a regression pin proven against the old behaviour.

**The mechanism, validated in this session against `d2c3720`.** Use a materialised old tree, not `git
stash` and not a worktree: it changes no repository state and needs no install.

```
BASE=$(git rev-parse HEAD)
git archive "$BASE" | tar -x -C /tmp/old-$BASE
ln -s "$PWD/node_modules" /tmp/old-$BASE/node_modules
cp packages/discovery/test/<new>.test.ts /tmp/old-$BASE/packages/discovery/test/
( cd /tmp/old-$BASE && node --test --test-reporter=spec packages/discovery/test/<new>.test.ts )
```

**Symlinking each workspace `@orchescope/<name>` to the old tree's own copy is mandatory.** Without it,
`@orchescope/traces/model-endpoints` resolves to the *current* source from inside the old tree, and defect
B's falsifier passes both ways, which is exactly the worthless test this rule exists to prevent.

Worked example, run in this session: `embedding-is-not-an-agent.test.ts` on `d2c3720^` gives
`tests 2 / pass 1 / fail 1` with `AssertionError: an embedding call produced a component` and actual
`[{ id: 'agent:embedtext' }, { id: 'model:embedding/unspecified' }]`; on the current tree it gives
`tests 2 / pass 2 / fail 0`. The two `tests / pass / fail` blocks are the transcript.

**Falsifier and guard are different assertions and must be labelled.** The falsifier must be observed
failing against the old tree; if it does not fail, it is not shipped. A guard is an assertion that passes
both ways on purpose, such as `stays quiet where there is no evidence`, which is exactly what AGENTS.md
requires of a new rule. A guard passing both ways is correct, not a defect. The test names say which is
which, because a reader cannot otherwise tell.

The falsifiers, and what each one would have to see to fail:

| fix | falsifier | fails against old behaviour because |
| --- | --- | --- |
| A, conjunction | ADK's tenth agent shape: keyword-only, `model` present, `tools` absent | `hasToolsAndModelKeys` requires both |
| A, class | `class X(Base)` from a foreign distribution | the net iterates `calls` only |
| A, decorator | `@step` from a foreign distribution | same |
| A, bound receiver | `this.c = new C(); this.c.chat({model})` | the call has no `origin` |
| A, provenance | `typing`, `@/alias`, first-party deep module produce nothing | today they are not excluded, so a disjunction would report them |
| B, host gate | `http://127.0.0.1:11434/v1/chat/completions` is a model call | `modelEndpointForHost` returns undefined |
| B, host extraction | `https://api.openai.com:443/v1/chat/completions` names `openai` statically | `hostOf` returns the authority with the port |
| B, honesty | an unrecognised host yields `unspecified`, never an invented provider | no such branch exists |
| B, same origin | `/api/chat/completions` mints no model | the question is unreachable today |
| C | the anchor keeps its `invokes_model` edge, its declared timeout, its prompt attribution and its provider qualification, under the new kind | the kind is in the identity, so the assertions are on the new id |

## Holes the completeness review found, and what they cost

Each was verified against source after it was reported.

**The re-export hole.** A third-party symbol re-exported through the repository's own module is refused
before any argument test: `from .llm import Agent` fails `namesLocalSpecifier`, and
`from myproject.llm import Agent` is caught by `namesLocalModule`
(`local-modules.ts:103-112`). The reader never opens `module.imports` of the local module, so the chain
cannot be followed even in principle. Wrapping an LLM library in an internal module is one of the most
common production shapes there is, and it is invisible to the current net and to every widening above.
Closing it means following a local specifier to the module it names and asking that module's imports where
the symbol came from. The symbol index already resolves across modules, so the machinery exists.

**Annotation-shaped declaration sites.** The brief asks the backstop to cover non-call declaration sites,
and this design read that as class bases plus decorators. `ParameterFact.annotation`,
`DefinitionFact.returnAnnotation` and `DefinitionFact.returns` (`packages/source-analysis/src/facts.ts`)
each carry a dotted name that can resolve to an import. `def handle(agent: Agent) -> AgentResult` names an
unclaimed distribution with no call and no construction. This is a fifth net, N5, and it is not in the
measurement above.

**Widening moves `findings.*`, on up to 41 entries.** `scanPopulationComplete`
(`packages/graph/src/analysis.ts:340-346`) requires **every** unsupported area to be `topology_incomplete`
with scope `prompt_use`. The first `unclaimed_imported_construction` on a repository flips it, which flips
`complete`, `acyclicityComplete`, `reachabilityComplete` and `narrownessComplete`, which stops
`unreachableDrafts` running and withholds the topology strength. Three rules consume it
(`static-policy.ts:848`, `:1265`, `:1477`). Measured: **41 of 49** corpus expectations record none of the
four unsupported populations, which is the upper bound on how many entries could lose
`scanPopulationComplete` the moment the backstop fires once. The corpus already absorbs this for the two
entries that carry a refusal today, so the mechanism is proven rather than speculative. My earlier framing
of the blast radius as `byKind` counts and new refusal keys was incomplete.

**`UnsupportedAreaKind` is closed and published.** `grep -l unclaimed_imported_construction schemas/*.json`
returns `system-graph.v1.json`, `report.v1.json` and `federation.v1.json`. And the kind's own doc comment
**is** the conjunction: "whose arguments carry both a tools-shaped name and a model-shaped name." A class
definition has no arguments, so that definition cannot be stretched over the new nets; it has to be
rewritten to something provenance-shaped. Two options, and this needs your decision: reuse the existing
kind and redefine a published term while moving no document, or mint a second kind and change three schema
documents. **Decided in ADR 0014:** reuse for the located site with a rewritten, provenance-shaped
definition, and mint exactly one kind for the tier B aggregate.

**The repository already holds several answers to "is this local", and the backstop must not fork another.**
`symbol-index.ts:68-81` already carries `ROOT_ALIASES = ['@/', '~/']` with its rationale written out: an
npm scope is never empty, so `@/lib/thing` cannot be a package. My alias proposal should reuse that, not
add a fifth copy. Likewise `decoratedDefinitions` at `packages/discovery/src/matching.ts:342-372` is an
existing origin-gated decorator scan used by three adapters; N3 belongs beside it as a name-free variant,
not as a new implementation.

**Layer 1 has a defect of exactly defect B's shape, and nobody assigned it.** MCP recognition has two
bases. Configuration files keyed on `mcpServers`/`servers` are genuinely protocol-shaped. But the SDK call
sites are gated on `SDK_PACKAGES = ['@modelcontextprotocol/sdk', 'mcp', 'fastmcp']`
(`packages/discovery/src/adapters/mcp.ts:38`), used both as the applicability gate (`:479-481`) and as
`adapter.packages` (`:238`). A three-entry distribution allowlist is structurally the same object as
defect B's twelve-entry host allowlist. **The invariant names MCP as layer 1, framework-blind, and half of
the MCP reader is not.** This is out of scope for the work you specified, and it is the next thing that
falsifies the invariant if it is left alone.

**Layer 0 can be silent before any of this runs.** `LANGUAGE_MARKERS`
(`packages/discovery/src/discover.ts:116-125`) is an eight-entry list, and its comment is honest about it:
"what a real repository turns out to contain rather than what a survey says exists." A repository written
in Elixir, Scala, Dart or Lua produces no `language_not_analysed` area at all, and the closed-world
sentence is emitted with nothing beside it. The backstop cannot help, because the file was never a
candidate. Extension-based detection of "a file this build did not read, in a language it does not name"
is the fix, and it is not in this design.

## Sequencing

Five landings, each with its own corpus gate, so a genuine regression cannot hide inside a wide diff.

1. **Provenance only, no widening.** Standard library, path aliases, first-party deep modules, and the
   `hostOf` authority correction. **Expected corpus movement: none**, because the only two recorded areas
   are `litellm` and `smolagents` and both are genuine third-party distributions. If this landing moves the
   corpus, something in it is wrong and it stops there.
2. **Defect A: widen the predicate.** Segment-stem disjunction, the declaration-builder suppressor,
   per-distribution sampling, detail moved into `reason`. Corpus moves; rebaseline entry by entry.
3. **The new nets.** N2 (Python), N3, N4, N5, the re-export bridge, and tier B's provenance-only floor.
   Corpus moves again, separately, so each net's contribution is readable on its own. The
   `scanPopulationComplete` flip lands here and it is the widest single effect in the whole change.
4. **Defect B.** Both halves of the join in one commit, after the `hostOf` correction has landed alone.
5. **Defect C.** Reclassification last, because it moves `byKind` on 25 entries and would mask anything
   above it.

The eight acceptance targets are pinned as corpus entries before landing 1, so every landing is measured
against them from the start.

## Pinning the acceptance targets

All eight are cloned at their exact pinned revisions and every file count matches the report's table
(12, 25, 59, 106, 17, 71, 20, 154). They become corpus entries with `kind`, `why`, and an expectation, and
they are regression inputs at any later revision, never unseen holdouts. T8 is pinned as a negative control
with its precision ceiling.

## What this still cannot do

Stated plainly, because the invariant is a claim and a claim needs its boundary.

- **JavaScript and TypeScript subclassing is invisible.** Verified: `class MyFlow extends Workflow`
  produces no `initializer` on its `DefinitionFact`. N2 works on Python today and needs an analyzer change
  in `packages/source-analysis/src/javascript/` to work on JavaScript. Until then a JS framework whose
  declaration form is subclassing degrades to whatever N1, N3 and N4 catch, and can still be silent.
- **T7 stays silent, and this design does not fix it.** `tinycode` declares five tools as plain Python dicts
  and a local `TOOLS` dispatch table, with no import from any distribution. An *imported*-construction net
  cannot see a declaration that imports nothing. Measured: 0 tier A hits. Closing this needs a different
  net, over local data structures, and it is a much larger precision problem.
- **T5's model half needs a protocol-vocabulary decision, not the host gate.** `/api/chat` is not an
  inference path today and removing the host gate does not change that.
- **A streamed or protobuf request with no readable `model` field** produces a runtime span the static side
  cannot name, and the reverse. The bare-name join needs a model name from somewhere.
- **A repository declaring one model id under two providers** loses the bare-name join, because
  `unspecified/<model>` removes the exact match that would have won.
- **Tier B is honest but not useful.** It names distributions this build did not read. It will list
  `pydantic`, `typing_extensions` and `rich` on T4 alongside `workflows`. That is true and it is noise, and
  the ranking that separates them is the part of this design with the least evidence behind it.
- **The MCP reader's three-entry SDK allowlist is not fixed here**, so layer 1 is only half framework-blind.
- **A language outside the eight in `LANGUAGE_MARKERS` is silent before any layer runs**, and no backstop
  in this design reaches it.
- **The display ceiling can still evict a located refusal**, and I have not chosen the remedy.

## What would break the invariant

- **A fix that requires a framework adapter.** If correctness on a new distribution needs a new entry in
  `DEFAULT_ADAPTERS`, layer 4 has become load-bearing and this record should be reopened.
- **The new kind entering `OBSERVABLE_KINDS`.** That is the 0.9.2 defect returning under a new name.
- **A tier A refusal that flips `agentSystemDetected`.** A refusal that becomes a component has crossed into
  layer 4 and is bound by ADR 0004 instead.
- **`open-agent-platform` gaining a component, or `orchescope-discovery` leaving its zero ceiling.** Those
  are the pinned canaries and they are what this design is measured against.
- **A tier B line that is dropped rather than aggregated.** Tier B's whole job is that it cannot be empty
  while a foreign construction exists. A cap that discards instead of counting turns the guarantee back
  into a likelihood.
